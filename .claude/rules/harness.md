# Harness rules: hooks, gates over the corpus, private remote, memory

Path-scoped: Claude Code loads this file when a file matching `paths:` is read or edited, not at session start. These rules moved here from `conventions.md`, `principles.md` and `critical_lessons.md` on 2026-10-22, to keep the always-loaded corpus under the combined-size limit. Same rules, narrower trigger.

## Conventions

### Data layout

- **What cannot be public is TRACKED on the private remote, not merely gitignored.** An ignore rule keeps a thing off the public repo and gives it nowhere else to live, so it survives on whichever machine made it and is silently absent on the other. Three tests, all required: it cannot be published (licensed, confidential, or a third party's provenance), it is wanted on more than one machine, and it is not regenerable from what IS public. `font_atlas/` and `_dev_scripts/_fonts_eval/` fail the third, `settings.json` and `.mcp.json` fail the second — those stay plainly ignored. Members today are `memory/` and the licensed faces in `fonts/`, each on its own orphan ref of `private-pids-jre-simulator`. The rule says where a thing goes ONCE it is judged unpublishable; it does not itself judge, and passing all three tests is not a reason to move something unasked — `audio_src/` passes and has deliberately not moved. That judgement is `TODO.md` § "What the project exposes publicly". (2026-09-03, author: *"the problematic to public face (memory fonts, etc) is tracked in the separate repo"*, then *"we will think about the public exposure part more carefully as a future direction"*.)
- **Narrative memory lives on the dedicated `private/memory` journal ref, not master.** `memory/` is untracked; the local files are an append-only write queue, the ref is the canonical store, and every write flows through `_harness/publish_memory.py`, which is a mechanical suffix-sync: idempotent, and it refuses edits to already-published blocks. Recap and session_init both run it, and `/commit` never stages `memory/**`. **The licensed font software rides the same private remote**, on a `fonts` ref through `_harness/sync_fonts.py`. Its file set is derived — ignored-and-untracked under `fonts/`, straight from git — because `.gitignore` already carries three patterns for Morisawa's naming variants and a fourth glob typed into the script would be a second copy of that answer. A pull only ever fills an ABSENT file; differing bytes are reported and left alone. `session_init` names a face this machine lacks, so the absence surfaces before a render raises inside `lcd_font`. Adding the remote: `CLAUDE.md` § Run.
- **The dedicated-ref bar for any other artifact needs all three:** always-latest semantics (an old checkout wants the newest copy, not its contemporary), high commit frequency, and zero diff-review value. Tests, domain docs, codifications and runtime assets fail it, because they version with the code: an old tag needs its own tests and assets, and rule diffs carry review value. (2026-07-23, triggered by multi-recap days interleaving memory-only commits between code commits.)
- **The narrative store is `private/memory`, and the public ref was DELETED on 2026-09-03.** Its 69 commits were copied to the private remote first, so no narrative was lost. Deletion is not retraction: anyone who fetched `origin/memory` while it existed still holds it, and every recap written before that date was public for months. What lifts going forward is the prohibition on writing such content at all — source-material provenance, a third-party name, something said in confidence now has somewhere to go. Two limits remain. Private means not-public rather than unreadable-by-the-host, so a real secret still does not belong there. And restating something that was on the public ref does not un-publish it. (2026-07-27, 2026-09-03.)

### Tooling

- **A classification written as a PATTERN needs the same breadth in every consumer, and nothing links the copies.** `.gitignore` learned to match the ShinGo family however Morisawa spells it, after `A-OTF Shin Go Pro DB.otf` arrived matching no existing rule. `/build`'s staged-folder cleanup asks the same question in a second place and still read `ShinGoPr6N-*`, so `ShinGoPro-DeBold.otf` arriving 2026-09-03 would have survived into the ship — the guard on the next line tests the family, so the build would have thrown rather than shipped, which is the only reason this was cheap. Both copies are text and no tool relates them, so when a member joins the class, grep the class's own subject rather than the one pattern you remember. Semantic tier of `conventions.md` § Tooling "Canonical-source duplication".
- **Structural renames: PostToolUse(Edit) hook auto-greps.** `stale_ref_hook.py` runs after every Edit — if 1–3 identifiers are removed, it greps the codebase and injects results as context. Review the output; historical entries in `critical_lessons.md` / `memory/*.md` are don't-touch. Common-word false positives are expected noise — judge by context.
- **Dep scanner: `_harness/check_deps.py`.** Run at `/build` pre-flight — verifies all production imports are in `[project.dependencies]`. Update `_INSTALL_TO_IMPORT` alias map in the script when a new dep's install name ≠ import name (e.g. `pywin32 → [win32, win32api, pywintypes]`). Excludes root preview/test harnesses (`preview_*.py`) from the production scan but keeps `plot_drive.py` (Report-button production path). See `critical_lessons.md §3`.
- **A `.gitignore` rule does not untrack anything — `git rm --cached` does, and nothing said so.** The two read as one step, so an ignore rule lands alone, the file keeps shipping in every clone, and the commit that added the rule reads as if it removed the file. 2026-08-08: `/fonts/ShinGoPr6N-*.otf` was added to `.gitignore` on the author's instruction and `git rm --cached` was never run; all three Morisawa faces stayed on `master` for eleven days while the commit message, `docs/wip/WIP_font_atlas.md` and `THIRD-PARTY.md § Fonts` each stated a clone no longer carried font software. The claim was in a compliance document, so its being false was the whole cost. Verify with `git ls-files <path>` — **not** `git check-ignore`, which prints nothing for a tracked file (that is its documented behaviour; `--no-index` is what makes it answer the pattern question) and so returns the same silence for "not ignored" and for "ignored but still tracked". Gated by the `no-tracked-ignored` pre-commit hook (`_dev_scripts/check_tracked_ignored.py`), repo ignores only so a machine-local global exclude over a deliberately tracked file is not a false positive.
- **Automated sensor tiers, tightest first.** Add a new sensor to the tightest tier whose false-positive rate is acceptable.

  | tier | scripts | what it does |
  |---|---|---|
  | pre-commit | `lint_primitives.py`, `check_fonts.py`, `check_spdx.py`, `check_tracked_ignored.py`, `check_rules_corpus.py` | blocks the commit |
  | build pre-flight | `check_deps.py` | blocks the build |
  | session-start | `check_harness.py`, `session_init.tools()` | reports; prints the tool inventory from each docstring's first line, derived rather than typed |
  | PostToolUse(Edit) | `stale_ref_hook.py`, `route_json_hook.py` | injects findings after an edit |
  | PreToolUse(Edit) | `edit_nudge_hook.py` | context reminders for display renderers, `route_loader`, `route.json` |
  | PreToolUse(Glob) | `unread_readme_hook.py` | flags a glob under a module dir whose README is unread this session; self-suppresses once read |
  | PreToolUse(many) | `audio_skill_hook.py` | surfaces `/sta-make` / `/pa-make` when a call touches `audio/` or `audio_src/` |
  | PreToolUse(Bash/PowerShell) | `no_generated_source_hook.py` | **denies** writing a tracked file through an inline program or redirect (shell shape × tracked path × write verb; bypass `CLAUDE_GENERATED_SOURCE_OK=1`) |
  | PreToolUse(Write/Bash/PowerShell) | `new_tool_hook.py` | non-blocking; on a `.py` that does not yet exist, emits the `_dev_scripts/` + `_harness/` inventory filtered by the verbs in the proposed filename |
- **The preloaded rules corpus is ratcheted, not capped.** `check_rules_corpus.py` measures entry count, total words, worst single entry and sibling cross-ref tails per rules file, and fails when any gets WORSE than a recorded baseline. It is a ratchet rather than the EDIT-CONTRACT's aspirational number because gating at the contract's cap would fail every commit and be disabled within a week: `principles.md` sat at 70 entries against its own 30 for months, which is the same shape as the MEMORY.md cap `docs.md` § "Compression buys ATTENTION" records at 97–100% violation. `tails` is hard at 0, since a tail is on both contracts' refuse-list and there is no legitimate first one; the word counts carry ~5% so a genuine new rule is not blocked, because a rule earns removal by being wrong and never by redundancy. **Lower a baseline whenever a distill pass improves it** — that is the ratchet tightening, and it is the only edit the script should normally need. (2026-09-29, the pass that took `principles.md` 70 → 49.)
- **Every gate over this corpus measures one file against itself, so none of them can see a skill that contradicts a rule.** A size or shape measure is a fact about a file; a contradiction is a fact about a pair, and the pair never loads together — a skill arrives only when triggered, a rules file every turn. So a violation can sit in a skill indefinitely with nothing anywhere reporting it: on 2026-09-29 an audit found four, including two skills instructing a commit offer that `principles.md` and `redlines.md` both forbid, unnoticed since May. The sweep is `/distill-rules` Step 2.5 — prohibition, then grep the skills for the act, then `git log -S` to see which side is newer.
- **A rule that loses to a competing instruction becomes a gate.** `no_generated_source_hook.py` is a gate rather than a bullet because the bullet already existed and lost: bypass-permissions mode injects "make file changes with sed, heredocs, or short scripts" every turn, and preloaded text cannot out-argue a 100%-attention-share instruction. (2026-08-26; `conventions.md` § "Editing source by GENERATING it".) The same reasoning pairs `new_tool_hook.py` with `session_init.tools()`, converting "discover tools before writing one" from a recollection into a push after 32 temp-directory scripts answered four questions the repo already had tools for.
- **A skill's frontmatter `triggers` are not a sensor.** They match the skill's own vocabulary ("trim sta", "sta_cut"), which real requests don't use ("finish the audio pooling"), so a workflow spec stays unread until handed over by hand. When a skill must fire for a whole domain, gate it on the paths that domain touches. 2026-08-08: *"i had enough of having to hand you skill when asking you to work on these."*
- **Sensor design: flag the violation, don't inject the rule.** A sensor outputs "error at line X" and stops. It does not remind Claude what the rule is. Injection is cognitive load; a flag is a signal. Each automation pays twice, in bugs prevented and in tokens: a 50-token nudge can prevent a 10k-token debugging session.
- **PreToolUse(Glob) hook mechanism.** PostToolUse(Glob) does NOT surface `additionalContext` — context injection only works from PostToolUse on Edit/Bash/PowerShell. For Glob hooks, use PreToolUse with `hookSpecificOutput` JSON: `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow", "additionalContext": "..."}}`. Self-suppression without temp files: `transcript_path` is available in hook stdin; scan `type='assistant'` JSONL entries and check `msg['message']['content']` for prior Read tool_uses of the target README.
- **Review-time structural-impact scan: `code-review-graph`.** `/review-dirty` (inherited by `/review-plus-fix-relentlessly`) runs a `code-review-graph` pre-scan before the lenses — `uvx code-review-graph` (NO `pyproject` dep; index lives in the user cache, never the repo), `impact` (blast-radius / callers-dependents) + `detect-changes` (test-gaps + risk), `PYTHONIOENCODING=utf-8` (its `--brief` panel crashes on cp1252 stdout), **fail-open** (any error → skip, never block). Feeds Lens 1 (who-calls) / Lens 4 (test-gaps) / INTEGRATION escalation. Mechanics live in `.claude/skills/review-dirty/SKILL.md`; the adopt-through-orchestration rationale is § "Natural adoption gates tool value" below. **An EMPTY graph reports zeros, not findings** — `status` saying `Nodes: 0 … Last updated: never` means no index was ever built, and `detect-changes` then prints `0 test gaps · risk 0.00` under a "Saved ~100% tokens" panel, which reads exactly like a clean bill of health. Check `Nodes:` before believing any zero (2026-08-10: measured on this repo — the same command went 0 gaps / risk 0.00 → 4 gaps / risk 0.80 purely from running `build` first). Deferred: the `enrich` PreToolUse(Edit) hook (edit-time who-calls push).
- **`claude mcp add … -- <cmd>` is unreliable in PowerShell** — PS eats the `--` separator (so `claude` misparses the server cmd's `--from`/`--context`), and the `.ps1`→`.exe` wrapper strips quotes from `add-json` JSON (`--%` doesn't survive either). Write `.mcp.json` directly with the Write tool instead — no shell quoting. 2026-06-11 (Serena setup).

## Principles

#### Natural adoption gates tool value — push through the harness, don't add a pull-MCP
A tool's worth is capped by whether it gets used *naturally*, and naturalness = **who owns the context-injection step**. A **pull** tool (an MCP the model must choose to call) loses to the reflex and sits unused — Serena is installed, `conventions.md` says "use it going forward," and grep still wins. To get used, the output must be **pushed**: a **skill step** (orchestrated work — the skill invokes it, so it can't be forgotten) or a **harness hook** (free-form work — injected at the decision). Judge a candidate by delivery shape FIRST, capability second.

**Why:** (2026-07-21) evaluating repo-mapping tools (repomix / aider repo-map / codebase-memory-mcp / code-review-graph) — every high-star MCP failed on *adoption*, not capability; the one adopted (code-review-graph) fit because `review+fix` is orchestrated, so the skill calls it.

**How to apply:**
- Adopt a capability through the harness's injection points (a `review-dirty` pre-flight step, a PreToolUse hook), not a discretionary `.mcp.json` server.
- "The agent may call it" → expect it unused. If you can't push it, it won't land.
