# Conventions — naming, style, tooling

Project-local style and naming choices. These don't shape major decisions; they keep code consistent. Each entry is short — "X uses Y" or "don't do Z."

## Naming

- **Use "sta" terminology** (not "departure_melody" or similar). Audio files, JSON fields, skill names, doc text — all use `sta`.
- **Folder structure carries metadata.** Diagram is extracted from `audio/<line>/<diagram>/` (e.g., `nambu/4027F/`). Don't flatten or rename.
- **`_*` prefix = preserved-but-not-shipped staging.** Examples: `audio/_archive/` (recordings the active diagram doesn't use, kept for future glob lookup), `audio/_mock/` (preview/test fixtures), `_dev_scripts/` (middlescript: audio splitters/validators, OCR-asset extractor, primitive-bans linter, dxcam + game-capture diagnostics), `_harness/` (hook sensors, build gate, session scripts), `_experiments/` (WIP not yet ready for project root), `_<feature>_calibration/` (gitignored source material that derives committed artifacts).
  - **Hard rule:** production code (project root + `displays/`) MUST NOT import from `_*/` paths. The presence of a production import is itself the signal that the file has graduated — promote it out (e.g. `_experiments/ocr.py` → `ocr.py` at project root, or `data_tools/plot_drive.py` → `plot_drive.py` after the 2026-04-30 incident; `data_tools/` was renamed to `_dev_scripts/` in the same incident). Folder placement carries dep-classification semantics — see [critical_lessons.md § "Lazy import ≠ optional dep"](critical_lessons.md) for the full pathology.
  - **Treatment by tools:** `release.ps1` classifies `audio/_*/` + `data/_*` as harness (not shipped); `/vibe-check` excludes code under `_*/` from production-scope reviews (Step 1) AND flags production imports of `_*/` as smell #10 (Step 2). **Both route pickers skip `_`-prefixed dirs in their `audio/` scan** (`setup.py` + `setup_tims/route_select.py`: `dirs[:] = [d for d in dirs if not d.startswith("_")]`) — so an `audio/_<line>/` WIP route is hidden from the picker AND the zip. (2026-07-15: `_joban` still listed because the scanners only special-cased literal `_mock`; the general prefix skip fixed both.)
- **Name patterns by cause, not discovery instance.** When a recurring pattern is documented in skills / docs (recording-source quirk, behavioral pattern, technique), name it by what DRIVES it (`hostile-recording pattern`, `source-driven transient`) — NOT by the first line / case where it was observed (`yamanote-style`, `keiyo lines have KAK`). Discovery-instance tagging creates false line-specificity: a reader sees "yamanote-style" and assumes pattern is Yamanote-only, missing that it applies to any recording with the same source-side property. 2026-05-12: sta-make skill tagged hostile-recording + KAK as `yamanote-style` / `keiyo lines`; user flagged that Yamanote has KAK too — both patterns are recording-source-driven, not line-specific. Skill text retagged generically; the discovery line gets a one-line origin note as illustration, not as the pattern's scope.

## Data layout

- **Centralized translations**: single `data/translations.json` for all lines, not per-line files.
- **`constants.py` is for cross-module values only.** Per-LCD-module sizes / positions / fonts live inline in that LCD module (in tuneable-params blocks or `__init__`). Each LCD type has its own module and may pick its own sizes; sharing across modules would force false uniformity. Only add to `constants.py` if a value is genuinely consumed by ≥ 2 modules (e.g., `STOPS_WIDTH` shared by future per-train lower displays, `TIME_SCALE` shared by app + display).

## Tooling

- **Pre-commit hooks: Black + primitive bans.** `.pre-commit-config.yaml` wires: Black (formatter, version-pinned to match `pyproject.toml`), `_dev_scripts/lint_primitives.py` — two hooks: `ban-production-primitives` (regex-grep for `pygame.font.SysFont`, `Path(__file__).parent`, `sys._MEIPASS`, `sys.frozen` outside `app_paths.py`, `_*/` production imports) and `ban-derivable-literals` (`--derivable`, AST-scan — see next bullet) — plus `_dev_scripts/check_fonts.py` (`.ttf` ban). Run `pre-commit install` once per clone. Don't run Black manually unless the hook isn't firing. Format-skip blocks wrap in `# fmt: off` / `# fmt: on` per UI code style.
- **Canonical-source duplication — a hardcoded literal re-stating a value that owns a single source, so the copy drifts silently.** Correct-at-authoring, so eyeball / dirty-diff review miss it (a hand-typed `VERSION="0.5.4"` shipped while the build was 0.6.0 — born in a `_dev_scripts/*_draft.py`, copied verbatim into production at promotion). Caught in two tiers: **mechanical facets** — version → `app_paths.display_version()`, bare bundled-asset path → `project_root()` — by the `ban-derivable-literals` pre-commit hook (`lint_primitives.py --derivable`, AST so docstrings/comments/error-strings don't false-positive; scope = production + `*_draft.py`, so a draft placeholder is caught at BIRTH not only at promotion). **Semantic facets** a linter can't reason about — special-case literal where a general predicate belongs (`=="_mock"` vs `startswith("_")`), color == a `tims_chrome` PALETTE constant, UI string bypassing `i18n.t`, route field via per-call `stop.get() or default` — by the **derivation-bypass scan** in [`/review-dirty`](../skills/review-dirty/SKILL.md) (facet-checklist lives there; runs over the whole module in FULL/MODULE scope, where committed-but-unchanged code is in scope). A literal is a violation ONLY when a canonical source exists — a tuneables-block magic number IS its own source. Generalizes the scattered instance-rules: path resolver ([critical_lessons § 4](critical_lessons.md)), fork-time re-verify (§ Display module structure below), PALETTE (§ UI code style), `finalize_route` closure ([principles § "JSON is input grammar"](principles.md)).
- **`.otf` fonts only.** `.ttf` cuts (Helvetica Neue specifically) have macron/diacritic artifacts at large sizes. The `fonts/` folder should never gain a `.ttf`. Enforced by `check_fonts.py` pre-commit hook.
- **TIMS chrome text = Noto Sans, AA-OFF native, no upscale.** The embedded-system "pixel" look is an ordinary gothic with **anti-aliasing OFF at the native display px** — NOT a pixel font, NOT bitmap strikes, NOT nearest-upscaling (×2 upscale thickens the stroke — tried + rejected). Font = **Noto Sans per-locale** (`NotoSans{JP,TC,SC}`, weight **Thin**, via `i18n.pixel_font_for_lang`): JP serves station names (always Japanese) + Latin/JP chrome but **tofus Chinese**, so the TC (zh_HK) / SC (zh_CN) siblings are required. Shipped as small static **Subset OTF** (keeps the `.otf`-only rule intact — no `/build` subsetting step). Size envelope **≤ ~40px native** — above that the single-stroke look breaks; nothing upscales to grow. Numerals = **full-width (全角) digits + separators on a monospace cell**; the status-band readout **unit** (`km/h` / `m`) renders in the SAME full-width fat forms as the digits, advanced **PROPORTIONALLY at ≤1px so the glyphs TOUCH** — NOT a uniform cell (a uniform cell sizes to the widest glyph and floats the narrow ones, which reads as bad spacing). The `/` is kept natural/narrow (the full-width `／` is ~2× the letters and balloons the run). `status_band._draw_unit_ss` / `_fullwidth`; `READOUT_UNIT_CELL_GAP` = the inter-glyph px. (Was half-width-natural via `blit_lowres` pre-2026-07-21; the fat full-width matches the digit look.) Vertical layout is **ink-based** (`_ink_vbox` / `_ink_line_h`): line stacking + box height use ink height, NOT `font.get_height()` (Noto's tall leading would balloon gaps), so `line_gap` is the true visual gap and boxes hug the text. `widgets.py` takes a **pre-resolved `Font`** — zero font-loading in widgets; fonts route through `i18n`. Supersedes the Ark single-face / k=2-ceiling / supersample rules.
- **Never `pygame.font.SysFont()` in production code.** Crashes on Chinese-locale Windows (`TypeError: expected str, bytes or os.PathLike object, not int`) because SysFont scans the Windows font registry, which fails on non-EN locales — original 2026-03-14 incident, recurred 2026-05-07 after the i18n chrome refactor regressed it. All chrome + LCD fonts load via `pygame.font.Font(str(project_root() / "fonts" / fname), ...)`. Enforcement points: CONTRACT blocks at `displays/train_models/*/upper_lcd.py`, comment block + `_LANG_CHROME_FONT` mapping in `i18n.py`. `_dev_scripts/` may keep SysFont — doesn't ship.
- **Mixed-script i18n chrome needs two fonts.** A chrome surface that renders both translated labels AND Japanese proper nouns (station names from route data) cannot use one font: the en chrome face (`HelveticaNeue`) is Latin-only and tofus kanji. Render chrome labels via the per-language `i18n.font()` and proper-noun chunks in a dedicated CJK face (`ShinGoPr6N` via a local `_get_name_font()`), and **baseline-align** them — place each chunk at `baseline - font.get_ascent()` against a shared baseline, because top-aligning at the same `y` misaligns the two (ascents differ, most visibly zh_CN `Noto` vs `ShinGo`). Both fonts still route through `app_paths.project_root()` (no SysFont, no bare `Path()`). First instance: auto-input debug panel (`auto_input/driver.py` `draw_debug_panel`, 2026-05-31) — CONTRACT block at the call site. **The same Latin-only gap tofus non-CJK glyphs too** — arrows `→` (U+2192), bullets `●` (U+25CF): route them through the CJK face in text (panel chip `●` / segment `→`), or draw a **vector primitive** for diagram / decorative uses (disclaimer flowchart arrows in `setup.py _draw_ocr_disclaimer_panel`, 2026-06-04). Symptom is en-only — zh locales render fine because their chrome face is already CJK.
- **Multi-locale chrome adapts to per-locale font metrics — coherence WITHIN a locale beats sameness ACROSS locales.** A chrome surface that renders the same element in `en` / `zh_HK` / `zh_CN` must adapt to each locale's font, not pin one face/size: (1) **Font = the locale's chrome face** (`i18n.font`), even for a Latin-only label (e.g. a model designation `E235-1000`) — pinning one Latin face (`HelveticaNeue` / Frutiger) for cross-locale sameness clashes beside same-row locale-font text (the `1654T` diagram code renders in ShinGo / Noto). (2) **Widget width derives from the label measured in the active font**, not a fixed px — ShinGo renders `E235-1000` ~30% wider than HelveticaNeue, so a fixed width clips in zh_HK. (3) **Stacked-line spacing advances by line 1's `get_ascent()` + a small fixed gap**, not full `get_height()` — Noto zh_CN's 18pt line height is 27px (heavy leading), so line-height spacing balloons the inter-line gap in that one locale; ascent-based keeps the visual gap coherent. First instance: setup-screen route rows + train-model dropdown (`setup.py`, 2026-06-21). Distinct from the two-font rule above (that's kanji-in-Latin-chrome tofu; this is font/size coherence of a shared element across locales).
- **Per-module UI-locale global must sync from `i18n.current_lang()` at the flow ENTRY, not sit at a module default.** Chrome TEXT keys off `i18n.t`→`_current_lang` (right language) but chrome FONT keys off the per-module `ACTIVE_LANG`; an unsynced global (module-default `"zh_HK"`) → zh_CN renders Simplified text in the TC face = **tofu**, en gets the wrong face. Sync at the flow root (`home.run()`: `ACTIVE_LANG = i18n.current_lang()` before the first render → sub-screens inherit on entry); the live-drive band already does it (`app.py` → `status_band.ACTIVE_LANG`). Invisible in dev/preview (they set the global themselves) — only the packaged entry regressed. 2026-07-15 blocker; full 114-site unify to one `i18n._current_lang` still deferred post-ship (TODO).
- **All bundled-asset path resolution via `app_paths.project_root()`.** Never `Path(__file__).parent`, never `sys._MEIPASS`, never inline `if sys.frozen:` branching, never a new local `app_root()` / `get_base_dir()` / `_project_root()` helper. The 2026-05-05 release shipped four separate crashes from authoring locality (each module's author solved the path-resolution problem in isolation, one with the wrong PyInstaller semantic). See [critical_lessons.md § "PyInstaller deployment-frame divergence"](critical_lessons.md). `_MEIPASS` is reserved for plotly's library bundle (`--collect-data plotly`), never project assets. Calibration tools, `_dev_scripts/`, and `_harness/` are exempt — they don't ship.
- **`old_version.py`** — keep. Intentionally retained as the pre-refactor monolithic reference even though nothing imports it. Don't propose deleting it during tidy passes.
- **Structural renames: PostToolUse(Edit) hook auto-greps.** `stale_ref_hook.py` runs after every Edit — if 1–3 identifiers are removed, it greps the codebase and injects results as context. Review the output; historical entries in `critical_lessons.md` / `memory/*.md` are don't-touch. Common-word false positives are expected noise — judge by context.
- **Dep scanner: `_harness/check_deps.py`.** Run at `/build` pre-flight — verifies all production imports are in `[project.dependencies]`. Update `_INSTALL_TO_IMPORT` alias map in the script when a new dep's install name ≠ import name (e.g. `pywin32 → [win32, win32api, pywintypes]`). Excludes root preview/test harnesses (`preview_*.py`) from the production scan but keeps `plot_drive.py` (Report-button production path). See `critical_lessons.md §3`.
- **Data-field additions must update `validate_data.py` in the same change.** A new `route.json` / data-catalog field (documented in `DATA_FORMAT.md`) with no validator check makes the validator silently PASS on it — drift is invisible until a manual audit. 2026-07-15 pre-release sweep found `model` / `line_code` / color-shape / the whole `translations_app.json` (locale + `{placeholder}` parity) unchecked after the TIMS + E235-0 cycle. Full-scan = the shipped-data gate (skips `_*/`); `--route` validates any path on demand.
- **Automated sensor tiers:** pre-commit (`lint_primitives.py`, `check_fonts.py`) → build pre-flight (`check_deps.py`) → session-start (`check_harness.py`) → PostToolUse(Edit) (`stale_ref_hook.py`, `route_json_hook.py`) → PreToolUse(Edit) (`edit_nudge_hook.py` — context reminders for display renderers, route_loader, route.json) → PreToolUse(Glob) (`unread_readme_hook.py` — flags glob under module dir if its README hasn't been Read this session; self-suppresses once read). Add new sensors to the tightest tier whose false-positive rate is acceptable. Dual ROI: each automation saves both bug-prevention AND token-usage (a 50-token nudge prevents a 10k-token debugging session). **Sensor design: flag violations directly (linter model), not inject rules into context.** A sensor outputs "error at line X" and stops — it does not remind Claude what the rule is. Injection is cognitive load; a flag is a signal.
- **Test suite + tier hierarchy: [`_tests/README.md`](../../_tests/README.md).** The tier taxonomy (T0 static · T1 unit · T2 contract · T3 invariant · T4 clean-frame · T5 smoke/exe; **rendering EXCLUDED = by-eye by design**) + per-tier EXISTS/GAP status live there; `_tests/run_all.py` is the live map (prints a loud `NO TESTS (gap)` per empty tier — gaps visible, never a silent pass), wired into `/build` pre-flight. **Existing gates are indexed by REFERENCE, not moved** (T0 = `lint_primitives`/`check_fonts`; T2 = root `validate_data.py`); only NEW tests (T1/T3/T4) live physically under `_tests/t<N>_<tier>/test_*.py` — e.g. OCR read-correctness graduated from the former `_dev_scripts/validate_ocr.py` into T3 `test_ocr_reads.py` (committed fixtures under `_tests/fixtures/ocr/`, regenerated by `extract_ocr_assets.py`). Plain exit-code scripts, **no pytest yet** (deferred — adopt when a tier fills enough that `parametrize`/fixtures cut code). Fill incrementally; regression-test-per-incident is the first fill. The class this backs: § Tooling "Canonical-source duplication" (T0 mechanical + T3 invariant).
- **PreToolUse(Glob) hook mechanism.** PostToolUse(Glob) does NOT surface `additionalContext` — context injection only works from PostToolUse on Edit/Bash/PowerShell. For Glob hooks, use PreToolUse with `hookSpecificOutput` JSON: `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow", "additionalContext": "..."}}`. Self-suppression without temp files: `transcript_path` is available in hook stdin; scan `type='assistant'` JSONL entries and check `msg['message']['content']` for prior Read tool_uses of the target README.
- **Hook scripts that output non-ASCII must call `sys.stdout.reconfigure(encoding="utf-8")` at entry.** Windows pipes default to cp1252; Japanese characters in validator output crash the hook silently without this. Pattern used in `route_json_hook.py`, `check_harness.py`, `check_deps.py`.
- **Avoid `FOO_<digits>x<digits>` style identifiers.** Pyright (the LSP backing the user's IDE) misparses identifiers containing a digit-letter-digit run like `CAPTURE_REGION_2560x1440` — symbol resolution breaks downstream (callers report "name not defined" even though Python accepts the identifier). Use underscore between the numeric groups instead: `CAPTURE_REGION_2560_1440`. Python lexer is fine either way; this is purely a tooling workaround. 2026-05-13 incident: capture-region refactor; renamed once Pyright kept flagging the import.
- **Iterative-preview screenshots: save + report the path, don't Read them back.** During visual tuning loops where the user is the visual judge (nudging angles/gaps/positions across rounds), write the screenshot and tell the user its path — don't Read the PNG into context each iteration; it burns tokens for no decision you're making. Read a render only when *you* must verify something (does it crash, did the element appear). 2026-05-29: user — *"for these kind of preview task, no read png to save you context."* **Save under the REPO ROOT as `screenshot_*.png`** (the `.gitignore` `screenshot_*.png` pattern keeps them untracked; repo-root paths are what the user opens) — NOT the scratchpad. 2026-07-06: user — *"all screenshot needs to be under project repo folder."*
  - **But never extract PRECISE structural facts (counts, segment cuts, alignment, member-per-row groupings) by reading a reference PHOTO or screenshot** — perception of compressed/photographed images is unreliable for exact counts, and confidently mis-reading one sends the whole calibration round the wrong way. Build a faithful headless replication (read the LIVE tuneables, mirror the algorithm) and read its TEXT output as ground truth instead. 2026-06-15/16: misread the Yamanote shinkansen wrap as 3+3 vs the IRL 4+2 twice off the reference PNG; resolved only by `_dev_scripts/_sim_panel_layout.py` (reads `_TUNEABLES_TRANSFER_PANEL` live, replicates `_build`+repair) producing the exact per-station groupings. The PNG is for the human visual judge; the algorithm is for precise facts. Cross-ref [principles.md § "Verify before claiming"](principles.md).
- **Prefer Serena MCP over grep for semantic code questions.** `find_referencing_symbols` (who-calls / is-orphaned), `find_symbol` (locate + body + signature), `get_symbols_overview` (file structure) answer via the LSP — grep is textual and can't tell a real caller from a comment/doc mention, so "is X dead" / "where's X called" via grep needs manual filtering. Grep stays for free-text + pattern sweeps. Server in `.mcp.json` (uvx-from-git, gitignored, per-machine). 2026-06-11: user — *"use it going forward."*
- **`claude mcp add … -- <cmd>` is unreliable in PowerShell** — PS eats the `--` separator (so `claude` misparses the server cmd's `--from`/`--context`), and the `.ps1`→`.exe` wrapper strips quotes from `add-json` JSON (`--%` doesn't survive either). Write `.mcp.json` directly with the Write tool instead — no shell quoting. 2026-06-11 (Serena setup).

## Display module structure

- **Shared display logic uses parent + per-model concrete.** When a display module has logic shared across train models, factor a parent into `displays/<module>.py` + a per-model concrete subclass into `displays/train_models/{model}/<module>.py` — real inheritance from day one even with one concrete model. Per-model tuneables (canvas sizes, fonts) stay in the concrete (per [Data layout](#data-layout)); only shared logic moves up. Counter-example: `UpperDisplay` / `LowerDisplay` are concrete-only because their bodies are entirely per-model rendering. First instance: `displays/transfer_info.py` (parent) + `displays/train_models/e235_1000/transfer_info.py` (concrete).
- **Forking a sibling-model renderer: copy primitives, don't reinvent.** When intentionally duplicating a per-model renderer for a new sub-series (e.g. `e235_0/` forked from `e235_1000/` for the Yamanote re-skin), copy the existing primitive functions (pentagon draw, dot draw, chevron geometry, time-circle, etc.) verbatim into the new module — even when "I could write that in 5 lines myself" feels true. Visual-fidelity primitives encode pixel-tuned constants from prior iteration rounds (e.g. `_draw_pentagon`'s asymmetric `rect_half_w_back=21, rect_half_w_apex=20`); rolling your own loses that calibration silently and the user has to re-iterate from scratch. Distinct from "Search before authoring common utility code" in [principles.md](principles.md) — that's about cross-cutting utilities; this is about intentional per-model duplication where copy is correct.
  - **Concept-level inheritance, not token-level transplant.** When the user names a shared concept (chevron, time circle, pentagon), find the sibling's *same-concept* primitive — full-route → full-route, not the first grep match. The sibling has multiple chevron paths (full-route asymmetric halo vs 8-station uniform-halo recipe); pick by structural role. Copy the STRUCTURAL pattern (gating logic, layered approach, shared `if gi == curr_stop:` gate, etc.); keep the concrete model's own visual params (colors, sizes) — those are model-specific. Surface "which sibling primitive is the same concept" before copying when ambiguous. The 2026-05-08 e235_0 time-circle iteration burned through 6 distinct color states partly because PASSED_COLOR (e235_1000's marker color) was transplanted instead of the structural curr_stop-gate pattern.
  - **Deployment-frame primitives don't inherit safely — re-verify against canonical homes.** Visual primitives copy verbatim, BUT deployment-frame primitives (font path resolution, asset path resolution — anything that should route through `app_paths.project_root()` per [critical_lessons.md § "PyInstaller deployment-frame divergence"](critical_lessons.md)) MUST be re-checked when forking, not blindly copied. The 2026-05-08 e235_0 fork inherited bare `pygame.font.Font("fonts/X.otf", N)` strings from e235_1000; both train models then perpetuated the same deployment-frame violation (worked in practice only because cwd happened to land at project root in dev + alongside-exe). **How to apply:** before copying a renderer, grep the source for `pygame.font.Font(`, `Path(__file__)`, bare asset strings (`"fonts/…"`, `"data/…"`), `sys._MEIPASS`, `sys.frozen` — confirm each routes through the canonical helper, then copy. (The bare-asset-string half is now also caught mechanically by `ban-derivable-literals` — see § Tooling "Canonical-source duplication".)
  - **Inherited slot/manager infra leaks parent bindings unless EVERY variant is overridden.** Distinct from copying primitives: when a sub-series *reuses* the sibling's `LowerDisplay`/manager (not just copies draw functions), the parent's `__init__` constructs per-mode/per-slot renderer instances AND shared components import the parent model's dimension constants. Overriding only the common path leaks the parent's elsewhere. Two instances, both 2026-06-15: (a) **per-mode renderers** — e235_0 swapped only `japanese_display` / `japanese_eight_display` (kanji/furigana), so ENGLISH mode still showed e235_1000's linear full-route + 8-station view; fix points `english_display` / `english_eight_display` at the same instances (one shared instance, not a new one, so animation state isn't re-triggered on mode change). (b) **dimension constants** — the shared transfer display imported e235_1000's `UPPER_HEIGHT` (117), mis-sizing e235_0's lower region by 13px; fix parametrizes the dim (default = sibling's value) and reads height from the actual surface (`surf.get_height()`), never importing one model's dimension constant into shared code. **How to apply:** when forking, enumerate every renderer slot × mode the manager dispatches AND every model-dimension a shared component reads — override/parametrize all of them, not just the kanji/common path.
- **Cross-cutting pygame-lifecycle concerns: wrap the call, don't guard each site.** When a concern must fire on EVERY `set_mode` / `flip` / `update` / `display.quit` — window pinning, frame capture, teardown locking — install a one-shot wrapper at app entry rather than adding a call at each site. Call sites are many and grow (`flip`/`update` alone span 18 files), so a scattered guard is a regression waiting for the next screen. Wrappers are idempotent (`getattr(fn, "_<x>_wrapped", False)` guard) and must never break the render loop (swallow their own exceptions). Instances: `window_utils.install_topmost_hook` (`set_mode` → re-pin topmost) · `frame_stream.install_present_hook` (`flip`/`update` → capture the completed frame) · `frame_stream.install_display_quit_guard` (`display.quit` → hold the frame lock across teardown). The pattern's origin is a regression that proves it: the monolith re-pinned after every `set_mode`, the modular rewrite kept the pin only in `app.py`, and the TIMS setup flow silently lost always-on-top. Distinct from `# CONTRACT:` pointers (those inform a reader; this makes forgetting impossible).
- **Single-slot, fixed-orientation marker → free polygon, not a parametric shape model.** When a marker is only ever drawn at ONE fixed screen position + orientation (the view re-centres on it — e.g. the current-stop marker that always sits at the same slot), don't build a parametric shape model (heading / side-length / tilt / pointiness knobs). Store its vertices as free-drag calibration data — the vertices ARE the shape, hand-placed against the IRL overlay. A parametric model spends its complexity on curve-following the marker doesn't have, while *failing* at the one thing that matters: matching the single photographed shape (no parameterisation can represent an arbitrary pentagon; a free vertex list trivially can). Keep the downstream pipeline (breathing = scale verts about centroid, halo = uniform edge-normal offset, dot) — only the shape source changes. First instance: e235_0 5-station current-stop pentagon (2026-06-12) — surfaced via `/third-man` after multiple failed home-plate-plus-knobs iterations; user confirmed it as the firm pattern for this class of problem. (Distinct from "copy primitives, don't reinvent" above — that's for markers that DO move/rotate across positions and need the calibrated geometry.)
- **Station-code badge typeface is fixed, not a parameter.** `displays/utils.draw_station_code_badge` hardcodes the face (`NeueFrutigerWorld-Bold`, the JR signage typeface) via a module-level cached `_badge_font(size)` — callers pass only point SIZES (`prefix_size` / `num_size` / `code_3_size`), never a font object. Don't re-add a font-face parameter "for flexibility": a wrong face is exactly how the 5-station badge first rendered wrong (ShinGo/Helvetica instead of Frutiger). Size stays caller-controlled because badges legitimately differ (upper 68px → 18/22pt ≈ 0.27/0.32 ratio; 8-station 22px → 8/11pt ≈ 0.36/0.5 — chunkier so tiny text stays legible, so a single fixed ratio can't serve both). 2026-06-12: user — *"DO NOT ever change the font … that function shouldn't even accept different font."*
- **WIP-doc → canonical-doc graduation.** Speculative or in-flight feature work lives in a `WIP_<topic>.md` doc with its own EDIT-CONTRACT (holds: pending designs, transitional diffs, calibration insights). When the feature stabilizes, the WIP doc dissolves into its canonical home and is deleted. Two precedents: `WIP_transfer_display.md` → `DISPLAY.md` (2026-05-05, when `render_transfer` promoted to production) and `WIP_E235_DISPLAYS.md` → new `DISPLAY_E235.md` (2026-05-07, when E235-0 lower-LCD circular renderer shipped). Trigger to graduate is named in the WIP doc itself; absorbing it into the canonical home is a single-commit restructure (no parallel-existence period).

## UI code style

- **Tuneable-params block.** Every UI draw method must expose its magic numbers (positions, sizes, offsets, gaps) as labeled local variables at the top of the method. All downstream coordinates derive from those. No scattered magic numbers. Rationale: the user fine-tunes visuals by nudging these values — they must be discoverable AND reactive (changing `badge_w` should recompute interior width, centering, text positions automatically). **Wrap the block in `# fmt: off` / `# fmt: on`** so Black preserves trailing-comment column alignment — the alignment is what makes the block scannable. Same wrapper applies to other alignment-critical sites: aligned dict-of-tuples (`_LANG_CHROME_FONT`-style), hex-range tables (CJK detection ranges), color-palette constant clusters. **Markers must be exact** — `# fmt: off` / `# fmt: on` only; trailing text on the directive line (e.g. `# fmt: off — preserve alignment`) is treated as a regular comment and Black formats through it.
- **Editor-compatible tuneables: module-level `_TUNEABLES_*` dict.** The method-local `# fmt: off` block above is the *predecessor*; the calibration-editor standard going forward is a module-top `_TUNEABLES_<ELEMENT>[_MODE]` dict the draw method reads each frame (direct key access — no per-call recompute of constants). To make an element editor-tunable: (1) extract its magic numbers into the dict following the **param-suffix convention** (`_x`/`_y`/`_w`/`_h`/`_color`/`_<edge>_offset` drive the editor's ruler/swatch visualization; a region's position+size goes in a sibling `_TUNEABLES_*_RECT` dict the draw method syncs via `RECT.update(...)` each frame); (2) keep/declare a hit-test rect; (3) add a `_REGISTRY` entry in `_dev_scripts/calibration_editor.py` (`rect_attr` + `dicts` + `target`); (4) smoke-test in `uv run preview_display.py --edit`. **Convert lazily** — only when an element is next touched for tuning; no eager backfill sweep. New train models wire elements from day one (`e235_0` is the golden-template fork-source). Full mechanics + the suffix table: `/calibration-editor` skill.
- **Comment dormant scaffolding explicitly.** When a helper is defined but intentionally uncalled, put a multi-line `# NOTE: deliberately NOT called from … yet` block above it explaining *why*, *when to wire it in*, and *what's reserved for it*. Without that signal, every reviewer-pass re-flags it as dead code.
- **User-facing labels use public language, not internal vocabulary.** When an internal/debug surface becomes user-visible (this project ships lightly-public), de-jargon the labels: translate layer/wire/jargon terms into words a non-developer reads. - **TIMS button interaction model — one graphics signal per logical condition, uniform across every setup screen.** (a) **Yellow** press flash (`press_transition` `state="pressed"`) = "registered" — EVERY clickable button; a locked/inactive button gets NO yellow (its click no-ops, gated on the same precondition that silvers it). (b) **Loading beat** (`press_transition` `blank_ms>0`, blanks below the band) = NAVIGATING buttons only (opens a screen / launches the sim / commits-and-returns); in-place actions (steppers, select-a-cell-that-stays) use `blank_ms=0`. (c) **Flash white** (`state="waiting"`, time-phase toggle) = "actionable next / current" — a gated action now ready (OCR起動-when-committed, 設定-when-changed, consent-OK-when-scrolled) or the current selection. (d) **Silver** (`chrome.DISABLED`) = inactive (next bullet). **Selection idiom:** a picked cell shows STEADY YELLOW when a separate confirm button (設定) carries the "proceed" flash; it FLASHES when the click itself commits (no confirm on the page, e.g. model-select). ## Contract Pointers in Code

When a function or class has a non-obvious contract that lives in a doc (`DISPLAY.md`, `DATA_FORMAT.md`, etc.) — and getting it wrong has caused or *clearly could cause* regressions — anchor a pointer in the code itself, at the top of the class or function body.

**Why.** "Read the doc first" instructions get bypassed when an agent has *partial* context that feels sufficient (real failure: an agent skipping `DISPLAY.md` for a lower-LCD bugfix because some preloaded content seemed to cover it). An in-code pointer is unavoidable — anyone editing the code reads the file first, so the pointer lands in their context at the moment of decision. Skipping it requires deliberate dismissal, not omission.

**Format** (terse, ~3 lines):

```python
# CONTRACT: <one-line summary>.
# See <DOC.md> § "<exact section heading>".
# <one-line context: what breaks if you skip the doc>.
```

**Bar for adding one** — non-obvious AND would clearly bite:
- ✅ Window invariants, mode-cycler timing rules, skip-animation state contracts, clear-bg confinements, "must be called unconditionally before X" ordering rules, recurring-review-false-positive sites.
- ❌ Routine functions whose behavior is obvious from the code itself, or where the contract is local and self-documenting.

**Don't substitute for the doc.** The pointer summarizes; the doc has the actual contract. Update the doc when the contract changes; keep the inline comment terse.
