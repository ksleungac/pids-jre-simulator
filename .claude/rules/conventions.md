# Conventions — naming, style, tooling

Project-local style and naming choices. These don't shape major decisions; they keep code consistent. Each entry is short — "X uses Y" or "don't do Z."

## Naming

- **Use "sta" terminology** (not "departure_melody" or similar). Audio files, JSON fields, skill names, doc text — all use `sta`.
- **Folder structure carries metadata.** Diagram is extracted from `audio/<line>/<diagram>/` (e.g., `nambu/4027F/`). Don't flatten or rename.
- **`_*` prefix = preserved-but-not-shipped staging.** Examples: `audio/_archive/` (recordings the active diagram doesn't use, kept for future glob lookup), `audio/_mock/` (preview/test fixtures), `_dev_scripts/` (middlescript: audio splitters/validators, OCR-asset extractor, primitive-bans linter, dxcam + game-capture diagnostics), `_harness/` (hook sensors, build gate, session scripts), `_experiments/` (WIP not yet ready for project root), `_<feature>_calibration/` (gitignored source material that derives committed artifacts).
  - **Hard rule:** production code (project root + `displays/`) MUST NOT import from `_*/` paths. A production import itself means the file has graduated — promote it out (e.g. `_experiments/ocr.py` → `ocr.py` at project root, or `data_tools/plot_drive.py` → `plot_drive.py` after the 2026-04-30 incident; `data_tools/` was renamed to `_dev_scripts/` in the same incident). Folder placement carries dep-classification semantics — see [critical_lessons.md § "Lazy import ≠ optional dep"](critical_lessons.md) for the full pathology.
  - **Treatment by tools:** `/build`'s staging step classifies `audio/_*/` + `data/_*` as harness (not shipped — via `$shipExclude` plus the tracked-only filter; `release.ps1` was retired in `9bfe431`); `/vibe-check` excludes code under `_*/` from production-scope reviews (Step 1) AND flags production imports of `_*/` as smell #10 (Step 2). **The route picker skips `_`-prefixed dirs in its `audio/` scan** (`tims/setup/route_select.py`: `dirs[:] = [d for d in dirs if not d.startswith("_")]`; the classic `setup.py` picker had the same skip and was retired 2026-07-30) — so an `audio/_<line>/` WIP route is hidden from the picker AND the zip. (2026-07-15: `_joban` still listed because the scanners only special-cased literal `_mock`; the general prefix skip fixed both.)
  - **A one-off measurement script is `_dev_scripts/_<question>.py`, TRACKED, with a docstring opening `"""Throwaway:"""` or `"""Ad-hoc:"""`** — seven precedents (`_classify_mask.py`, `_inspect_mask.py`, `_montage_panels.py`, `_sim_panel_layout.py`, `_bake_preview.py`, …). Named for the question it answers, never for the attempt. Tracked is the point, not an oversight: the author sees it in the diff and can object as it appears; the throwaway-or-keep call is recorded at WRITE time in the docstring rather than remembered; and a probe that turns out to matter is already kept — `_sim_panel_layout.py` was written as a one-off and is now cited in § UI code style as the instrument that settled the Yamanote 4+2 grouping after two by-eye misreads. **Never the OS temp dir**: it is the one location invisible to git AND to the session, so you cannot open your own previous attempt and write a new file instead — 2026-08-26 produced 32 files for four questions that way. `_experiments/` is NOT this; it stays what its `.gitignore` entry says, PoC folders that will graduate. Renders the author will see go to the repo root as `screenshot_*.png` (§ Tooling). Rules: [redlines.md](redlines.md); [principles.md § "Prototype INSIDE the code that will hold it"](principles.md).
- **Name patterns by cause, not discovery instance.** When a recurring pattern is documented in skills / docs (recording-source quirk, behavioral pattern, technique), name it by what DRIVES it (`hostile-recording pattern`, `source-driven transient`) — NOT by the first line / case where it was observed (`yamanote-style`, `keiyo lines have KAK`). Discovery-instance tagging creates false line-specificity: a reader sees "yamanote-style" and assumes pattern is Yamanote-only, missing that it applies to any recording with the same source-side property. 2026-05-12: sta-make skill tagged hostile-recording + KAK as `yamanote-style` / `keiyo lines`; user flagged that Yamanote has KAK too — both patterns are recording-source-driven, not line-specific. Skill text retagged generically; the discovery line gets a one-line origin note as illustration, not as the pattern's scope.
- **i18n translation keys are a data namespace, not a module path.** `translations_app.json` keys (`setup_tims.band.home`, read via `i18n.t`) are opaque identifiers — they don't track the Python module that reads them. A module rename (`setup_tims/` → `tims/setup/`) leaves its key namespace unchanged; renaming the keys would mean editing every locale in `translations_app.json` + every call site for zero functional gain, and any code↔JSON mismatch silently returns the raw key. (2026-07-22: the `tims/` package restructure kept the `setup_tims.*` keys deliberately — review+fix was primed not to flag them as stale.)

## Data layout

- **Centralized translations**: single `data/translations.json` for all lines, not per-line files.
- **`route.json` is authored content — a UI bug gets fixed in the code, not by editing the data.** It is touchable, but it is not the reach-for when a screen behaves wrong. 2026-07-27 (#59): the TIMS picker offered Yamanote's 大崎 twice, and the two entries turned out to be non-redundant (`stops[0]` has `pa: []` as the loop origin, `stops[29]` carries `pa: ["30"]`, the closing まもなく) — deleting the trailing stop would have dropped that announcement and moved the terminus. The defect was the picker offering the terminus as a start at all. User: *"you should never touch route.json … it breaks our data"*, then *"you can touch it however usually not touched when on these kind of things."*
- **Before calling a data value wrong, read that field's `docs/DATA_FORMAT.md` entry.** A field with a documented grammar has values that look like typos and are not. 2026-08-20: `"さいたま 新都心"` was flagged as a stray space — twice — off a `' '.join(names)` readout, when `DATA_FORMAT` documents a space in `name` as a line-break instruction and uses that exact string as its example. The tell is that the evidence was a rendering of my own tool output rather than the field's definition. Author: *"yes, it is, and you should read data format before acting like that."* Cheap check, and it also stops the second flag: an unanswered first one is not a reason to re-raise.
- **`constants.py` is for cross-module values only.** Per-LCD-module sizes / positions / fonts live inline in that LCD module (in tuneable-params blocks or `__init__`). Each LCD type has its own module and may pick its own sizes; sharing across modules would force false uniformity. Only add to `constants.py` if a value is genuinely consumed by ≥ 2 modules (e.g., `STOPS_WIDTH` shared by future per-train lower displays, `TIME_SCALE` shared by app + display).
- **Narrative memory lives on the dedicated `origin/memory` journal ref, NOT master.** `memory/` is untracked (gitignored); local files are the append-only write queue, `origin/memory` the canonical store, and every write flows through `_harness/publish_memory.py` (mechanical suffix-sync — idempotent, refuses edits to published blocks/entries; recap + session_init run it; `/commit` never stages `memory/**`). **Dedicated-ref bar for any other artifact — ALL three required:** always-latest semantics (an old checkout wants the LATEST copy, not its contemporary) + high commit frequency + zero diff-review value. Tests / domain docs / codifications / runtime assets fail it — they version WITH the code (an old tag needs its own tests/docs/assets; rule diffs carry review value). 2026-07-23; trigger was multi-recap days interleaving several memory-only commits between code commits. **`origin/memory` is a ref on the PUBLIC repo — narrative memory is a publishing surface, not a private notebook.** Local files being gitignored makes it feel private; anyone can `git fetch origin memory`. Anything that shouldn't be public (source-material provenance, third-party names, anything said in confidence) does not go in a recap, and there is no "write it in memory instead" escape hatch. 2026-07-27. **This posture is being retired (decided 2026-08-18):** the repo is now search-indexed and the author wants a private store going forward — [#112 "Move narrative memory off the public ref to a private store"](https://github.com/ksleungac/pids-jre-simulator/issues/112). Until that lands the rule above holds unchanged, and it keeps holding afterwards for everything ALREADY on the ref — a private store does not retract what is published.

## Tooling

- **Pre-commit hooks: Black + primitive bans.** `.pre-commit-config.yaml` wires: Black (formatter, version-pinned to match `pyproject.toml`), `_dev_scripts/lint_primitives.py` — two hooks: `ban-production-primitives` (regex-grep for `pygame.font.SysFont`, `Path(__file__).parent`, `sys._MEIPASS`, `sys.frozen` outside `app_paths.py`, `_*/` production imports) and `ban-derivable-literals` (`--derivable`, AST-scan — see next bullet) — plus `_dev_scripts/check_fonts.py` (`.ttf` ban) and `_dev_scripts/check_spdx.py` (`# SPDX-License-Identifier: MIT` in every `.py`'s first 3 lines). Run `pre-commit install` once per clone. Don't run Black manually unless the hook isn't firing. Format-skip blocks wrap in `# fmt: off` / `# fmt: on` per UI code style. **Black's `--exclude` REPLACES its default ignore list (`.venv`, `.git`, `build`…) rather than adding to it — use `--extend-exclude`, or just pass the file list.** 2026-08-08: `black --check . --exclude '^old_version\.py$'` started walking `.venv` and had to be killed after two minutes; `git ls-files '*.py' | xargs black --check` finished in seconds and is the honest scope anyway (tracked files are what the hook sees).
- **Canonical-source duplication — a hardcoded literal re-stating a value that owns a single source, so the copy drifts silently.** Correct-at-authoring, so eyeball / dirty-diff review miss it (a hand-typed `VERSION="0.5.4"` shipped while the build was 0.6.0 — born in a `_dev_scripts/*_draft.py`, copied verbatim into production at promotion). Caught in two tiers: **mechanical facets** — version → `app_paths.display_version()`, bare bundled-asset path → `project_root()` — by the `ban-derivable-literals` pre-commit hook (`lint_primitives.py --derivable`, AST so docstrings/comments/error-strings don't false-positive; scope = production + `*_draft.py`, so a draft placeholder is caught at BIRTH not only at promotion). **Semantic facets** a linter can't reason about — special-case literal where a general predicate belongs (`=="_mock"` vs `startswith("_")`), color == a `tims.chrome` PALETTE constant, UI string bypassing `i18n.t`, route field via per-call `stop.get() or default`, a parametric model re-stating a shape an authored asset already owns (hand-placed Catmull-Rom waypoints vs the band mask PNG — derive dependent geometry FROM the asset, e.g. `_extract_band_centerline`'s per-row mask centroid, #51) — by the **derivation-bypass scan** in [`/review-dirty`](../skills/review-dirty/SKILL.md) (facet-checklist lives there; runs over the whole module in FULL/MODULE scope, where committed-but-unchanged code is in scope). A literal is a violation ONLY when a canonical source exists — a tuneables-block magic number IS its own source. Generalizes the scattered instance-rules: path resolver ([critical_lessons § 4](critical_lessons.md)), fork-time re-verify (§ Display module structure below), PALETTE (§ UI code style), `finalize_route` closure ([principles § "JSON is input grammar"](principles.md)).
- **`.otf` fonts only.** `.ttf` cuts (Helvetica Neue specifically) have macron/diacritic artifacts at large sizes. The `fonts/` folder should never gain a `.ttf`. Enforced by `check_fonts.py` pre-commit hook.
- **TIMS chrome text = Noto Sans, AA-OFF native, no upscale.** The embedded-system "pixel" look is an ordinary gothic with **anti-aliasing OFF at the native display px** — NOT a pixel font, NOT bitmap strikes, NOT nearest-upscaling (×2 upscale thickens the stroke — tried + rejected). Font = **Noto Sans per-locale** (`NotoSans{JP,TC,SC}`, weight **Thin**, via `i18n.pixel_font_for_lang`): JP serves station names (always Japanese) + Latin/JP chrome but **tofus Chinese**, so the TC (zh_HK) / SC (zh_CN) siblings are required. Shipped as small static **Subset OTF** (keeps the `.otf`-only rule intact — no `/build` subsetting step). Size envelope **≤ ~40px native** — above that the single-stroke look breaks; nothing upscales to grow. Numerals = **full-width (全角) digits + separators on a monospace cell**; the status-band readout **unit** (`km/h` / `m`) renders in the SAME full-width fat forms as the digits, advanced **PROPORTIONALLY at ≤1px so the glyphs TOUCH** — NOT a uniform cell (a uniform cell sizes to the widest glyph and floats the narrow ones, which reads as bad spacing). The `/` is kept natural/narrow (the full-width `／` is ~2× the letters and balloons the run). `tims.band._draw_unit_ss` / `_fullwidth`; `READOUT_UNIT_CELL_GAP` = the inter-glyph px. (Was half-width-natural via `blit_lowres` pre-2026-07-21; the fat full-width matches the digit look.) Vertical layout is **ink-based** (`_ink_vbox` / `_ink_line_h`): line stacking + box height use ink height, NOT `font.get_height()` (Noto's tall leading would balloon gaps), so `line_gap` is the true visual gap and boxes hug the text. `tims/widgets.py` takes a **pre-resolved `Font`** — zero font-loading in widgets; fonts route through `i18n`. Supersedes the Ark single-face / k=2-ceiling / supersample rules.
- **Never `pygame.font.SysFont()` in production code.** Crashes on Chinese-locale Windows (`TypeError: expected str, bytes or os.PathLike object, not int`) because SysFont scans the Windows font registry, which fails on non-EN locales — original 2026-03-14 incident, recurred 2026-05-07 after the i18n chrome refactor regressed it. Chrome fonts load via `pygame.font.Font(str(project_root() / "fonts" / fname), ...)`. Enforcement points: CONTRACT blocks at `displays/train_models/*/upper_lcd.py`, comment block + `_LANG_PIXEL_FONT` mapping in `i18n.py`. `_dev_scripts/` may keep SysFont — doesn't ship.
- **LCD fonts resolve through `font_atlas.lcd_font(face, size)` — never a bare `pygame.font.Font`, and declare the text with `draws=`.** ShinGo is served from a pre-rendered atlas in a build that ships no font software, so a bare construct works in dev (the fonts are there) and raises in that build — invisible-in-dev, the [critical_lessons §4](critical_lessons.md) shape. Which families are baked is one tuple, `font_atlas.ATLAS_FACES`; every font goes through `lcd_font` regardless, so no call site decides. **New drawn text is a two-part edit**: the string, plus a `draws=` declaration naming where it comes from — `at("audio/*/route.json:stops[].name")` for data, `lit("次は")` for a source literal, with `replace=` / `split=` / `suffix=` for text the renderer derives. The atlas is cooked from those declarations, so coverage does not depend on any state being reachable; `lcd_font` validates every draw against the declaration in dev, so an undeclared string fails on the first frame that draws it rather than in a shipped build. A **font SIZE is part of the atlas key**, so `/build` re-bakes every run — never hand-edit a baked atlas or assume an existing one covers a nudged size. `docs/wip/WIP_font_atlas.md` holds the design; `displays/utils.py::compose_text_parts` is the only place LCD text layout exists.
- **Mixed-script i18n chrome needs two fonts.** A chrome surface that renders both translated labels AND Japanese proper nouns (station names from route data) cannot use one font: the en chrome face (`HelveticaNeue`) is Latin-only and tofus kanji. Render chrome labels via the per-language chrome face (`i18n.pixel_font_for_lang`) and proper-noun chunks in a dedicated CJK face (via a local `_get_name_font()`), and **baseline-align** them — place each chunk at `baseline - font.get_ascent()` against a shared baseline, because top-aligning at the same `y` misaligns the two (ascents differ, most visibly zh_CN `Noto` vs `ShinGo`). Both fonts still route through `app_paths.project_root()` (no SysFont, no bare `Path()`). First instance: auto-input debug panel (`auto_input/driver.py` `draw_debug_panel`, 2026-05-31) — CONTRACT block at the call site. **The same Latin-only gap tofus non-CJK glyphs too** — arrows `→` (U+2192), bullets `●` (U+25CF): route them through the CJK face in text (panel chip `●` / segment `→`), or draw a **vector primitive** for diagram / decorative uses (disclaimer flowchart arrows — originally `setup.py _draw_ocr_disclaimer_panel` 2026-06-04, now `tims/setup/ocr_setting.py`). Symptom is en-only — zh locales render fine because their chrome face is already CJK.
- **Multi-locale chrome adapts to per-locale font metrics — coherence WITHIN a locale beats sameness ACROSS locales.** A chrome surface that renders the same element in `en` / `zh_HK` / `zh_CN` must adapt to each locale's font, not pin one face/size: (1) **Font = the locale's chrome face** (`i18n.pixel_font_for_lang`), even for a Latin-only label (e.g. a model designation `E235-1000`) — pinning one Latin face (`HelveticaNeue` / Frutiger) for cross-locale sameness clashes beside same-row locale-font text (the `1654T` diagram code renders in ShinGo / Noto). (2) **Widget width derives from the label measured in the active font**, not a fixed px — ShinGo renders `E235-1000` ~30% wider than HelveticaNeue, so a fixed width clips in zh_HK. (3) **Stacked-line spacing advances by line 1's `get_ascent()` + a small fixed gap**, not full `get_height()` — Noto zh_CN's 18pt line height is 27px (heavy leading), so line-height spacing balloons the inter-line gap in that one locale; ascent-based keeps the visual gap coherent. First instance: classic setup-screen route rows + train-model dropdown (2026-06-21); that screen was retired 2026-07-30, but the rule still governs every TIMS surface that renders one element across locales. Distinct from the two-font rule above (that's kanji-in-Latin-chrome tofu; this is font/size coherence of a shared element across locales).
- **Per-module UI-locale global must sync from `i18n.current_lang()` at the flow ENTRY, not sit at a module default.** Chrome TEXT keys off `i18n.t`→`_current_lang` (right language) but chrome FONT keys off the per-module `ACTIVE_LANG`; an unsynced global (module-default `"zh_HK"`) → zh_CN renders Simplified text in the TC face = **tofu**, en gets the wrong face. Sync at the flow root (`home.run()`: `ACTIVE_LANG = i18n.current_lang()` before the first render → sub-screens inherit on entry); the live-drive band already does it (`app.py` → `status_band.ACTIVE_LANG`). Invisible in dev/preview (they set the global themselves) — only the packaged entry regressed. 2026-07-15 blocker; full 114-site unify to one `i18n._current_lang` still deferred post-ship (TODO).
- **All bundled-asset path resolution via `app_paths.project_root()`.** Never `Path(__file__).parent`, never `sys._MEIPASS`, never inline `if sys.frozen:` branching, never a new local `app_root()` / `get_base_dir()` / `_project_root()` helper. The 2026-05-05 release shipped four separate crashes from authoring locality (each module's author solved the path-resolution problem in isolation, one with the wrong PyInstaller semantic). See [critical_lessons.md § "PyInstaller deployment-frame divergence"](critical_lessons.md). `_MEIPASS` is reserved for plotly's library bundle (`--collect-data plotly`), never project assets. Calibration tools, `_dev_scripts/`, and `_harness/` are exempt — they don't ship.
- **`old_version.py`** — keep. Intentionally retained as the pre-refactor monolithic reference even though nothing imports it. Don't propose deleting it during tidy passes.
- **Structural renames: PostToolUse(Edit) hook auto-greps.** `stale_ref_hook.py` runs after every Edit — if 1–3 identifiers are removed, it greps the codebase and injects results as context. Review the output; historical entries in `critical_lessons.md` / `memory/*.md` are don't-touch. Common-word false positives are expected noise — judge by context.
- **A screen that runs BEFORE the one that narrows the choice must be built from the UNION of the candidates, never from the first.** The earlier screen has no way to know which candidate the user will land on, so reading `candidates[0]` silently drops everything only the others offer — and the screen still looks complete, which is why nobody reports it. `tims/setup/route_select.py` picked the start station before the diagram, from `variants[0]`: **four shipped lines could not be started at 34 of their stations** (南武線 14, 宇都宮線 10, 京浜東北線 6, 埼京線 4), because the express diagram sorts first alphabetically and it was the all-stations stops that vanished. Found 2026-08-22 only because a new diagram made the line's own origin unreachable; the author had noticed the symptom — *"no wonder i felt like some screens are so less stations"* — without a way to name it. **The union's companion: any invariant the earlier screen applies must be applied again by the later filter**, or the two fork — the same defect left a start that TERMINATES one diagram still offering that diagram, so the drive opened on its last stop. Give the invariant one named home (`_departable_stops`) and have both call it. Same family as the next bullet: nothing type-checks either half.
- **Name coupling across a boundary has no compiler — dispatch on a canonical TOKEN, and every key a consumer reads needs a producer.** Two facets of the same silent-failure class: nothing type-checks a string match or a `dict.get`, so both degrade to a no-op rather than an error. (a) **Control flow keyed on prose inside a message.** `_dev_scripts/capture_game.py` dispatched with `"fire departure PA" in event`; renaming the event strings to match production disarmed every synthetic PageDown while the script still *printed* the events, so it looked healthy and fired nothing. Dispatch on the leading token (`event.startswith("FIRE_DEPARTURE")`) and let the human-readable tail carry live numbers freely. (b) **A key read but never written.** `tims/band.py` read `reentry_pending` to draw the amber "Re-aligning…" chip and the driver never published it — a documented feature that could not appear, for weeks, with no error anywhere. When adding a status/telemetry key, grep both directions: every writer has a reader, every reader has a writer. Both found 2026-07-21 (#82). Related but distinct from the `stale_ref_hook` (§ "Structural renames"), which greps *identifiers* — a string literal's CONTENTS and a dict key are invisible to it.
- **When the deliverable IS a table / list / measurement set, render it in the chat message — tool output is not shown to the user.** Bash and script stdout render to claude, not reliably to the user, so "the table above" points at nothing they can see. Applies whenever the output IS the answer (a proposal table, a diff of current vs proposed, a classified file list); a tool call whose result only feeds claude's next step needs no echo. 2026-07-25: presented the Chūō `sta_cut` proposal as "Table above" — user: *"SHOW it TO ME?"*.
- **ffmpeg is an external binary, not a Python dep — a second PC can lack it entirely.** The audio pipeline (`trim_sta_silence.py`, `trim_pa_silence.py`, every splice recipe in `/sta-make`, the verifiers' interactive trim) shells out to `ffmpeg`, so it appears in no `pyproject.toml` group and `check_deps.py` cannot see it. A machine without it fails with a bare `FileNotFoundError: [WinError 2]` from `subprocess`, which reads as a broken script rather than a missing tool. `_find_ffmpeg()` in the verifiers searches PATH plus the usual winget/chocolatey locations; when none hit, `uv run --with imageio-ffmpeg python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"` yields a static build with no system install — copy it to `C:/ffmpeg/bin/ffmpeg.exe` (already on the search list) to make it durable. 2026-07-25: the Chūō STA trim hit this on the second PC.
- **A native exe called from the Bash tool takes WINDOWS paths, and ffmpeg's concat demuxer answers a bad one with a short file and exit 0.** `$(pwd)` under Git Bash yields the MSYS form (`/d/pids_jre_simulator`), which ffmpeg resolves as `C:/d/…` — so a concat list built with it points at nothing. It then prints `Impossible to open` / `Error during demuxing`, **skips that entry, writes the remaining ones, and exits 0**, so `set -e` does not fire and the output is a valid mp3 of the wrong length. 2026-08-12: a 48.7 s splice came out 20.6 s and only the duration check caught it. Build paths for native binaries as `D:/…` (or `cygpath -w`), and after any concat assert the output duration equals the sum of the inputs — the exit code is not the gate. Same family as the PowerShell `2>&1` bullet below: the shell's convenience and the binary's expectations disagree silently. **And a concat whose duration checks out can still be wrong at the JOIN.** An mp3 frame depends on a bit reservoir that does not survive a stream-copy boundary, so the first appended frame decodes as a burst: 2026-08-20, appending 0.5 s to a PA put a **+9.0 dBFS** click into an otherwise −3.0 dBFS file, at exactly the seam, and the duration assertion passed because the length was right. The author heard it. When the pieces are CONTIGUOUS in one source — which is the usual case when lengthening a cut — do not concat at all: widen the single `-ss/-to` window, which has no seam by construction. Reach for concat only when the pieces genuinely come from different places.
- **Editing source by GENERATING it is one escape level too many — use Edit/Write instead.** A string literal you write INTO a file has its escapes interpreted by the writer first, so `"
"` in a `python - <<'PY'` heredoc reaches the file as a real newline. 2026-08-20 that broke `validate_data.py` twice in one edit (once in a comment, once in `if "
" in rem:`), each time as a `SyntaxError: unterminated string literal` pointing at a line that looked fine in the heredoc. Bypass-permissions mode nudges toward Bash for file work; this is the case where Bash is the worse tool. If a script genuinely must emit an escape, build it as `chr(92) + "n"` rather than escaping the escape.
- **Dep scanner: `_harness/check_deps.py`.** Run at `/build` pre-flight — verifies all production imports are in `[project.dependencies]`. Update `_INSTALL_TO_IMPORT` alias map in the script when a new dep's install name ≠ import name (e.g. `pywin32 → [win32, win32api, pywintypes]`). Excludes root preview/test harnesses (`preview_*.py`) from the production scan but keeps `plot_drive.py` (Report-button production path). See `critical_lessons.md §3`.
- **Data-field additions must update `validate_data.py` in the same change.** A new `route.json` / data-catalog field (documented in `docs/DATA_FORMAT.md`) with no validator check makes the validator silently PASS on it — drift is invisible until a manual audit. 2026-07-15 pre-release sweep found `model` / `line_code` / color-shape / the whole `translations_app.json` (locale + `{placeholder}` parity) unchecked after the TIMS + E235-0 cycle. Full-scan = the shipped-data gate (skips `_*/`); `--route` validates any path on demand.
- **A new asset class must update `THIRD-PARTY.md` in the same change.** `LICENSE` (MIT) covers authored code + docs only; every other class — audio recordings, fonts, operator marks, reference photographs, assets derived from third-party software — is carved out and inventoried in `THIRD-PARTY.md`. An asset added with no entry silently widens what the grant *appears* to cover, and nothing mechanical catches it (a license scanner reads `LICENSE`, not the tree); the harm is a forker relying on an apparent grant. **Attribution-bearing classes are itemized** — the 3 CC BY-SA 4.0 Commons icons carry author + license + the modification made, and that itemization IS the compliance. **Everything else is disclaimed by category** with its rights holder named: a per-file inventory of unlicensed material is a target list, not a disclaimer. 2026-07-27: `data/` turned out to mix authored JSON with 37 third-party operator marks, so "this directory is mine" is not a safe classification unit — classify per file class, not per folder.

## Display module structure

- **A new model or a new view is spec-first — read [docs/DISPLAY.md § "Specifying a new display"](../../docs/DISPLAY.md) BEFORE writing any of it.** Whole-display basics (aspect → upper/lower divide → backgrounds → canvas) are settled and drawn first, ratios are measured by script and never by eye, and each view gets its own drill-down session with the author whose output is that view's spec. The pointer lives here because the workflow fires when no renderer file exists yet, so the PreToolUse(Edit) display nudge cannot reach it. Small tuning of an already-calibrated element is exempt — that goes straight to `/calibration-editor`.
- **Shared display logic uses parent + per-model concrete.** When a display module has logic shared across train models, factor a parent into `displays/<module>.py` + a per-model concrete subclass into `displays/train_models/{model}/<module>.py` — real inheritance from day one even with one concrete model. Per-model tuneables (canvas sizes, fonts) stay in the concrete (per [Data layout](#data-layout)); only shared logic moves up. **Split by rendering-vs-coordination, not by class name** — a manager's per-mode/per-slot RENDERING is per-model, but its COORDINATION (what's on screen, when it may change, what state drives it) is cross-model and belongs in the parent. Instances: `displays/transfer_info.py` (first) · `displays/lower_lcd.py` (`LowerDisplayBase` = slot cycle + force-switch + frame swap; the concretes keep renderer construction, `_pick_renderer`, `draw`). Counter-example: `UpperDisplay` stays concrete-only — its body is entirely per-model rendering. **A split is overdue when** a cross-model consumer (`ChangeScheduler`) can only reach its contract because one model happened to fork another's concrete — 2026-07-21, e235_0 satisfied the scheduler purely by subclassing e235_1000's `LowerDisplay`, so a model written standalone would have satisfied none of it.
- **Forking a sibling-model renderer: copy primitives, don't reinvent.** When intentionally duplicating a per-model renderer for a new sub-series (e.g. `e235_0/` forked from `e235_1000/` for the Yamanote re-skin), copy the existing primitive functions (pentagon draw, dot draw, chevron geometry, time-circle, etc.) verbatim into the new module — even when "I could write that in 5 lines myself" feels true. Visual-fidelity primitives encode pixel-tuned constants from prior iteration rounds (e.g. `_draw_pentagon`'s asymmetric `rect_half_w_back=21, rect_half_w_apex=20`); rolling your own loses that calibration silently and the user has to re-iterate from scratch. Distinct from "Search before authoring common utility code" in [principles.md](principles.md) — that's about cross-cutting utilities; this is about intentional per-model duplication where copy is correct.
  - **Concept-level inheritance, not token-level transplant.** When the user names a shared concept (chevron, time circle, pentagon), find the sibling's *same-concept* primitive — full-route → full-route, not the first grep match. The sibling has multiple chevron paths (full-route asymmetric halo vs 8-station uniform-halo recipe); pick by structural role. Copy the STRUCTURAL pattern (gating logic, layered approach, shared `if gi == curr_stop:` gate, etc.); keep the concrete model's own visual params (colors, sizes) — those are model-specific. Surface "which sibling primitive is the same concept" before copying when ambiguous. The 2026-05-08 e235_0 time-circle iteration burned through 6 distinct color states partly because PASSED_COLOR (e235_1000's marker color) was transplanted instead of the structural curr_stop-gate pattern.
  - **Deployment-frame primitives don't inherit safely — re-verify against canonical homes.** Visual primitives copy verbatim, BUT deployment-frame primitives (font path resolution, asset path resolution — anything that should route through `app_paths.project_root()` per [critical_lessons.md § "PyInstaller deployment-frame divergence"](critical_lessons.md)) MUST be re-checked when forking, not blindly copied. (The bare-asset-string half is now also caught mechanically by `ban-derivable-literals` — see § Tooling "Canonical-source duplication".)
  - **Inherited slot/manager infra leaks parent bindings unless EVERY variant is overridden.** Distinct from copying primitives: when a sub-series *reuses* the sibling's `LowerDisplay`/manager (not just copies draw functions), the parent's `__init__` constructs per-mode/per-slot renderer instances AND shared components import the parent model's dimension constants. Overriding only the common path leaks the parent's elsewhere. - **Cross-cutting pygame-lifecycle concerns: wrap the call, don't guard each site.** When a concern must fire on EVERY `set_mode` / `flip` / `update` / `display.quit` — window pinning, frame capture, teardown locking — install a one-shot wrapper at app entry rather than adding a call at each site. Call sites are many and grow (`flip`/`update` alone span 18 files), so a scattered guard is a regression waiting for the next screen. Wrappers are idempotent (`getattr(fn, "_<x>_wrapped", False)` guard) and must never break the render loop (swallow their own exceptions). Distinct from `# CONTRACT:` pointers (those inform a reader; this makes forgetting impossible).
- **Single-slot, fixed-orientation marker → free polygon, not a parametric shape model.** When a marker is only ever drawn at ONE fixed screen position + orientation (the view re-centres on it — e.g. the current-stop marker that always sits at the same slot), don't build a parametric shape model (heading / side-length / tilt / pointiness knobs). Store its vertices as free-drag calibration data — the vertices ARE the shape, hand-placed against the IRL overlay. A parametric model spends its complexity on curve-following the marker doesn't have, while *failing* at the one thing that matters: matching the single photographed shape (no parameterisation can represent an arbitrary pentagon; a free vertex list trivially can). Keep the downstream pipeline (breathing = scale verts about centroid, halo = uniform edge-normal offset, dot) — only the shape source changes. ## UI code style

- **A key whose action depends on state must be EDGE-triggered, not throttled.** `keyboard.is_pressed` is level-triggered and the drive loop polls at 30 fps, so a held key re-enters its branch every ~33 ms. That is harmless where the action is idempotent or self-gating (Page Down no-ops while PA plays — its held-key retry is deliberate, `pending_next_pa` depends on it), and a bug where the branch is chosen from CURRENT state: one Page Up press started the melody on poll 1 and, 33 ms later, took the it's-already-playing branch. A `wait()` throttle only narrows the window — 200 ms still sits inside an 80–200 ms keypress — and the semantic being implemented is "press AGAIN", which is the edge. Sample once per frame above the dispatch chain, act on the up→down transition, and keep the level test for chain ordering so a held key still masks the keys below it. 2026-08-11: reported as "the STA sometimes won't replay from the head"; the fix is `_pageup_was_down` in `app.py::_handle_input_main`, locked by T1 `test_playback.py`.
- **Tuneable-params block.** Every UI draw method must expose its magic numbers (positions, sizes, offsets, gaps) as labeled local variables at the top of the method. All downstream coordinates derive from those. No scattered magic numbers. Rationale: the user fine-tunes visuals by nudging these values — they must be discoverable AND reactive (changing `badge_w` should recompute interior width, centering, text positions automatically). **Wrap the block in `# fmt: off` / `# fmt: on`** so Black preserves trailing-comment column alignment — the alignment is what makes the block scannable. Same wrapper applies to other alignment-critical sites: aligned dict-of-tuples (`_LANG_PIXEL_FONT`-style), hex-range tables (CJK detection ranges), color-palette constant clusters. **Markers must be exact** — `# fmt: off` / `# fmt: on` only; trailing text on the directive line (e.g. `# fmt: off — preserve alignment`) is treated as a regular comment and Black formats through it.
- **A tuneable a downstream gate quantizes must be AUTHORED in the gate's unit.** When a mechanism transforms a parameter's effective value (a change-floor deferring a dwell, a grid snapping a position, a clamp bounding a range), a value written in the raw unit stops describing behavior: the lower-LCD `TRANSFER` slot was written `6.0` seconds and *rendered* 8s, because the 4s change floor deferred its expiry to the next allowed moment. Correct-at-authoring and silently wrong forever after. Fix = express the parameter in the gate's own unit (whole **beats**, `displays/base.py` `beats(n)`, which rejects fractions) so written == observed by construction, and validate at construction rather than trusting the author. A mismatch between the source number and a measured one exposes it — measure the effective value once per tuneable class rather than assuming the written value ships. Distinct from the tuneables-block rules above (those are about DISCOVERABILITY of a number; this is about the number being TRUE). 2026-07-21: user — *"we should just re-design the scheduling here, not scheduler"* — the mechanism was sound; the schedule it executed was never authored, only accumulated.
- **Editor-compatible tuneables: module-level `_TUNEABLES_*` dict.** The method-local `# fmt: off` block above is the *predecessor*; the calibration-editor standard going forward is a module-top `_TUNEABLES_<ELEMENT>[_MODE]` dict the draw method reads each frame (direct key access — no per-call recompute of constants). To make an element editor-tunable: (1) extract its magic numbers into the dict following the **param-suffix convention** (`_x`/`_y`/`_w`/`_h`/`_color`/`_<edge>_offset` drive the editor's ruler/swatch visualization; a region's position+size goes in a sibling `_TUNEABLES_*_RECT` dict the draw method syncs via `RECT.update(...)` each frame); (2) keep/declare a hit-test rect; (3) add a `_REGISTRY` entry in `_dev_scripts/calibration_editor.py` (`rect_attr` + `dicts` + `target`); (4) smoke-test in `uv run preview_display.py --edit`. **Convert lazily** — only when an element is next touched for tuning; no eager backfill sweep. New train models wire elements from day one (`e235_0` is the golden-template fork-source). Full mechanics + the suffix table: `/calibration-editor` skill.
- **`pygame.Font.render` CLIPS a glyph that overflows its own surface, and a monospaced cell clips one wider than the cell.** Two silent losses of ink in the same layout code, neither raising anything. (a) **Vertical.** `render` returns a surface exactly `get_height()` tall — `ascent + |descent|` — and at small sizes FreeType's grid-fitting inflates a glyph past that. Only ever one pixel, but a pixel of ink: over the 251 characters E233-0 draws it hits 向 城 成 片 行 越 at size 26 and 越 at 29, and `行` is on every destination. By size 38 nothing overflows. Render below the threshold at a whole multiple above it and resolve down (`_cell_scale`, `_CELL_MIN_RENDER`); the factor derives per size, so an element already large enough pays nothing. Two bonuses: the downscale is real antialiasing, and the glyph gets its TRUE proportions rather than grid-fitted ones — 東's ink is 1.000 of the em at 26 and 0.950 at 80, and the reference agrees with 0.950. (b) **Horizontal.** Kana carry side bearing and sit inside a narrow cell; a dense kanji fills its em edge to edge and hangs off the row surface — 次 lost 2px at the left. Measure the overhang over the glyphs actually drawn, pad the surface, and return the pad so the caller still positions the cell origin. **Any figure fitted against the pre-fix raster must be re-fitted**, not kept: the resample changes what was measured. 2026-08-25, both found by the author's eye, neither by any gate — all three references read `ただいま`, so no reference frame could have shown either.
- **A depth cue that works by DARKENING fails at the black end of the range — mix toward the face, not toward black.** On a near-black element, "the shaded side is darker" has nowhere to go: the shaded face and the surface it belongs to both land on black and merge into one flat mass, so the relief the cue was drawing disappears. The fix is to mix the shaded surface *toward its own face colour* rather than toward black — it still reads as the darker of the two, and stays distinguishable. Symmetrically, a highlight on a near-white element has to mix toward the face rather than toward white. 2026-08-21: the departure-bell cap's side wall was `mix(lo, black, 0.35)`, which turned a proud black button into a tall black slab with no visible thickness (`departure_bell.py` `cap_wall_mix`). Relevant anywhere an element is drawn near either end of the tone range, which on this project means most things sitting on the LCD's black.
- **A fail-soft handler on a PER-FRAME call reports once and then suppresses — never a blanket `except: pass`.** The thing a silent swallow hides is usually not the failure it was written for; it is a bug in the guarded call itself, and the guard then never runs and never says so. 2026-08-23: the bell window's topmost re-pin was written `except Exception: pass` because it runs 15×/s, and a missing `_SWP_NOMOVE` constant made every call raise `NameError` into it. The window silently stopped being always-on-top and nothing anywhere reported it; the symptom looked like SDL dropping the style. A one-shot flag (`self._pin_failed`) keeps the console quiet and still makes the first failure visible. Same family as [principles.md § "A measurement is a claim…"](principles.md)'s "a check that has never been observed to fail has not been shown to work" — a guard that has never spoken has not been shown to run.
- **Comment dormant scaffolding explicitly.** When a helper is defined but intentionally uncalled, put a multi-line `# NOTE: deliberately NOT called from … yet` block above it explaining *why*, *when to wire it in*, and *what's reserved for it*. Without that signal, every reviewer-pass re-flags it as dead code.
- **User-facing labels use public language, not internal vocabulary.** When an internal/debug surface becomes user-visible (this project ships lightly-public), de-jargon the labels: translate layer/wire/jargon terms into words a non-developer reads. Debug-panel pass (2026-05-31): `badge:`→`state:`, `Auto-fired`→`Auto-played`, internal fire-names `departure`/`at-station`→public `Next stop`/`At station`, `Game Sync`→`Auto-PA`. Keep deliberately-unlocalized technical terms (`OCR`) only when the user has already seeded them with end users — annotate the exception inline. User: *"this debug panel was our internal jargons, I need to carry this out in a somewhat publically understandable format."* **An internal STATUS FLAG surfaces as the tier the user gets, never as our process.** `ResolutionProfile.verified` is a real distinction worth showing, but "已實機驗證 1080P / 1440P / 4K" tells the reader what WE did; the OCR consent panel pairs a "tested on …" line with an "other … also work, but are not yet tested" line — same flag, framed as what they can expect. The correction was framing, not omission — dropping the distinction entirely was also wrong.
- **TIMS button interaction model — one graphics signal per logical condition, uniform across every setup screen.** (a) **Yellow** press flash (`press_transition` `state="pressed"`) = "registered" — EVERY clickable button; a locked/inactive button gets NO yellow (its click no-ops, gated on the same precondition that silvers it). (c) **Flash white** (`state="waiting"`, time-phase toggle) = "actionable next / current" — a gated action now ready (OCR起動-when-committed, 設定-when-changed, consent-OK-when-scrolled) or the current selection. (d) **Silver** (`chrome.DISABLED`) = inactive (next bullet). **Selection idiom:** a picked cell shows STEADY YELLOW when a separate confirm button (設定) carries the "proceed" flash; it FLASHES when the click itself commits (no confirm on the page, e.g. model-select). - **Disabled / unavailable TIMS button = a desaturated SILVER palette, not a dark scrim.** A grayed bevel button renders via the silver overlay — NOT a translucent dark scrim on the blue button (a scrim reads "shadowed / pressed," not "disabled"; silver reads inactive, matching the IRL TIMS 番台選択 grayed entries). ## Contract Pointers in Code

When a function or class has a non-obvious contract that lives in a doc (`docs/DISPLAY.md`, `docs/DATA_FORMAT.md`, etc.) — and getting it wrong has caused or *clearly could cause* regressions — anchor a pointer in the code itself, at the top of the class or function body.

**Why.** "Read the doc first" instructions get bypassed when an agent has *partial* context that feels sufficient (real failure: an agent skipping `docs/DISPLAY.md` for a lower-LCD bugfix because some preloaded content seemed to cover it). An in-code pointer is unavoidable — anyone editing the code reads the file first, so the pointer lands in their context at the moment of decision. Skipping it requires deliberate dismissal, not omission.

**Format** (terse, ~3 lines):

```python
# CONTRACT: <one-line summary>.
# See <DOC.md> § "<exact section heading>".
# <one-line context: what breaks if you skip the doc>.
```

**Bar for adding one** — non-obvious AND would clearly bite:
- ✅ Window invariants, mode-cycler timing rules, skip-animation state contracts, clear-bg confinements, "must be called unconditionally before X" ordering rules, recurring-review-false-positive sites.
- ❌ Routine functions whose behavior is obvious from the code itself, or where the contract is local and self-documenting.

**Don't substitute for the doc.** The pointer summarizes; the doc has the actual contract. Update the doc when the contract changes; keep the inline comment terse.
