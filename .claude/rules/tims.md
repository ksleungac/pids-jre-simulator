# TIMS and app-chrome rules: setup flow, status band, i18n chrome, window

Path-scoped: Claude Code loads this file when a file matching `paths:` is read or edited, not at session start. These rules moved here from `conventions.md`, `principles.md` and `critical_lessons.md` on 2026-10-22, to keep the always-loaded corpus under the combined-size limit. Same rules, narrower trigger.

## Conventions

### Naming

- **i18n translation keys are a data namespace, not a module path.** `translations_app.json` keys (`setup_tims.band.home`, read via `i18n.t`) are opaque identifiers — they don't track the Python module that reads them. A module rename (`setup_tims/` → `tims/setup/`) leaves its key namespace unchanged; renaming the keys would mean editing every locale in `translations_app.json` + every call site for zero functional gain, and any code↔JSON mismatch silently returns the raw key. (2026-07-22: the `tims/` package restructure kept the `setup_tims.*` keys deliberately — review+fix was primed not to flag them as stale.)

### Tooling

- **TIMS chrome text is Noto Sans, anti-aliasing off, at native size with no upscale.** The embedded-system "pixel" look is an ordinary gothic with AA off at the native display px. It is not a pixel font, not bitmap strikes, and not nearest-upscaling: a ×2 upscale thickens the stroke, tried and rejected. The face is `NotoSans{JP,TC,SC}` in weight **Thin** via `i18n.pixel_font_for_lang`. JP serves station names and Latin/JP chrome but tofus Chinese, so the TC (zh_HK) and SC (zh_CN) siblings are required. All three ship as small static subset OTFs, which keeps the `.otf`-only rule intact with no `/build` subsetting step. The size envelope is ≤ ~40px native; above that the single-stroke look breaks and nothing upscales to grow.
  - **Numerals are full-width (全角) digits and separators on a monospace cell.** The status-band readout unit (`km/h`, `m`) renders in the same full-width forms as the digits, advanced proportionally at ≤1px so the glyphs touch. A uniform cell would size to the widest glyph and float the narrow ones, which reads as bad spacing. The `/` stays natural and narrow, since the full-width `／` is about twice the letters and balloons the run. See `tims.band._draw_unit_ss` / `_fullwidth`, with `READOUT_UNIT_CELL_GAP` as the inter-glyph px.
  - **Vertical layout is ink-based** (`_ink_vbox`, `_ink_line_h`): line stacking and box height use ink height rather than `font.get_height()`, because Noto's tall leading would balloon the gaps. So `line_gap` is the true visual gap and boxes hug the text. `tims/widgets.py` takes a pre-resolved `Font`, doing zero font loading itself; fonts route through `i18n`.
- **Never `pygame.font.SysFont()` in production code.** Crashes on Chinese-locale Windows (`TypeError: expected str, bytes or os.PathLike object, not int`) because SysFont scans the Windows font registry, which fails on non-EN locales — original 2026-03-14 incident, recurred 2026-05-07 after the i18n chrome refactor regressed it. Chrome fonts load via `pygame.font.Font(str(project_root() / "fonts" / fname), ...)`. Enforcement points: CONTRACT blocks at `displays/train_models/*/upper_lcd.py`, comment block + `_LANG_PIXEL_FONT` mapping in `i18n.py`. `_dev_scripts/` may keep SysFont — doesn't ship.
- **Mixed-script i18n chrome needs two fonts.** A chrome surface that renders both translated labels AND Japanese proper nouns (station names from route data) cannot use one font: the en chrome face (`HelveticaNeue`) is Latin-only and tofus kanji. Render chrome labels via the per-language chrome face (`i18n.pixel_font_for_lang`) and proper-noun chunks in a dedicated CJK face (via a local `_get_name_font()`), and **baseline-align** them — place each chunk at `baseline - font.get_ascent()` against a shared baseline, because top-aligning at the same `y` misaligns the two (ascents differ, most visibly zh_CN `Noto` vs `ShinGo`). Both fonts still route through `app_paths.project_root()` (no SysFont, no bare `Path()`). First instance: auto-input debug panel (`auto_input/driver.py` `draw_debug_panel`, 2026-05-31) — CONTRACT block at the call site. **The same Latin-only gap tofus non-CJK glyphs too** — arrows `→` (U+2192), bullets `●` (U+25CF): route them through the CJK face in text (panel chip `●` / segment `→`), or draw a **vector primitive** for diagram / decorative uses (disclaimer flowchart arrows — originally `setup.py _draw_ocr_disclaimer_panel` 2026-06-04, now `tims/setup/ocr_setting.py`). Symptom is en-only — zh locales render fine because their chrome face is already CJK.
- **Multi-locale chrome adapts to per-locale font metrics: coherence within a locale beats sameness across locales.** A chrome surface rendering the same element in `en` / `zh_HK` / `zh_CN` adapts to each locale's font rather than pinning one face and size.
  - **The font is the locale's chrome face** (`i18n.pixel_font_for_lang`), even for a Latin-only label such as the model designation `E235-1000`. Pinning one Latin face for cross-locale sameness clashes beside same-row locale-font text, since the `1654T` diagram code renders in ShinGo or Noto.
  - **Widget width derives from the label measured in the active font**, never a fixed px. ShinGo renders `E235-1000` about 30% wider than HelveticaNeue, so a fixed width clips in zh_HK.
  - **Stacked-line spacing advances by line 1's `get_ascent()` plus a small fixed gap**, not full `get_height()`. Noto zh_CN's 18pt line height is 27px, so line-height spacing balloons the inter-line gap in that one locale while ascent-based spacing stays coherent.
  - First instance was the classic setup-screen route rows and train-model dropdown (2026-06-21). That screen was retired, but the rule governs every TIMS surface rendering one element across locales.
- **Per-module UI-locale global must sync from `i18n.current_lang()` at the flow ENTRY, not sit at a module default.** Chrome TEXT keys off `i18n.t`→`_current_lang` (right language) but chrome FONT keys off the per-module `ACTIVE_LANG`; an unsynced global (module-default `"zh_HK"`) → zh_CN renders Simplified text in the TC face = **tofu**, en gets the wrong face. Sync at the flow root (`home.run()`: `ACTIVE_LANG = i18n.current_lang()` before the first render → sub-screens inherit on entry); the live-drive band already does it (`app.py` → `status_band.ACTIVE_LANG`). Invisible in dev/preview (they set the global themselves) — only the packaged entry regressed. 2026-07-15 blocker; full 114-site unify to one `i18n._current_lang` still deferred post-ship (TODO).
- **A screen that runs BEFORE the one that narrows the choice must be built from the UNION of the candidates, never from the first.** The earlier screen cannot know which candidate the user will land on, so reading `candidates[0]` silently drops everything only the others offer, and the screen still looks complete. `tims/setup/route_select.py` picked the start station before the diagram, from `variants[0]`: four shipped lines could not be started at 34 of their stations (南武線 14, 宇都宮線 10, 京浜東北線 6, 埼京線 4), because the express diagram sorts first alphabetically and it was the all-stations stops that vanished. Found 2026-08-22 only when a new diagram made a line's own origin unreachable; the author had noticed the symptom without a way to name it: *"no wonder i felt like some screens are so less stations"*.
- **Any invariant the earlier screen applies must be applied again by the later filter.** Otherwise the two fork: the same defect left a start that terminates one diagram still offering that diagram, so the drive opened on its last stop. Give the invariant one named home (`_departable_stops`) and have both call it.
- **A local HTTP server that gains a WRITE endpoint changes threat model, loopback included — check the CALLER, not just the body.** Any page the user visits can reach `127.0.0.1`, and a CORS-*simple* `POST` (`Content-Type: text/plain`) is sent with no preflight. So "bound to loopback" stops meaning "only this app can talk to it" the moment the endpoint does something. Two headers close it. Require `application/json`, which forces a preflight the server answers with 501, having no `do_OPTIONS`. And check `Host` against the addresses actually bound, which also closes DNS rebinding on the READ endpoints. Both are what a same-origin client already sends, so nothing legitimate changes. 2026-08-19: `frame_stream`'s `POST /tap` shipped validating its JSON body and nothing about who sent it, while the design doc still described `--stream` as "zero network exposure" — true of the read-only stage 1 it was written for. The posture is a property of the ENDPOINT SET, not of the bind address, so re-read it whenever the set grows.

### Display module structure

- **Cross-cutting pygame-lifecycle concerns: wrap the call, don't guard each site.** When a concern must fire on EVERY `set_mode` / `flip` / `update` / `display.quit` — window pinning, frame capture, teardown locking — install a one-shot wrapper at app entry rather than adding a call at each site. Call sites are many and grow (`flip`/`update` alone span 18 files), so a scattered guard is a regression waiting for the next screen. Wrappers are idempotent (`getattr(fn, "_<x>_wrapped", False)` guard) and must never break the render loop (swallow their own exceptions). Instances: `window_utils.install_topmost_hook` (`set_mode` → re-pin topmost) · `frame_stream.install_present_hook` (`flip`/`update` → capture the completed frame) · `frame_stream.install_display_quit_guard` (`display.quit` → hold the frame lock across teardown). The pattern's origin is a regression: the monolith re-pinned after every `set_mode`, the modular rewrite kept the pin only in `app.py`, and the TIMS setup flow silently lost always-on-top.
- **A recorded PLATFORM fact is a measurement with a date on it, not a settled result.** Re-measure the one your design turns on, because the wrong way round is often the one that looks like working. 2026-08-23: `WIP_departure_bell.md` recorded that `WS_EX_NOACTIVATE` fails to keep focus and that remember-and-restore via `SetForegroundWindow` works. Measured, it is the reverse — handing the foreground away desynchronises SDL's mouse-focus tracking, so the first press registers and every later one is swallowed, 1 of 4 presses against 6 of 6 under the style the doc had ruled out. SDL activates a window when it shows it whatever its ex-style says, so a window created visible steals focus once at birth and the style looks inert. Building on the record would have shipped a box that works once per launch.

### UI code style

- **A key whose action depends on state must be EDGE-triggered, not throttled.** `keyboard.is_pressed` is level-triggered and the drive loop polls at 30 fps, so a held key re-enters its branch every ~33 ms. That is harmless where the action is idempotent or self-gating (Page Down no-ops while PA plays — its held-key retry is deliberate, `pending_next_pa` depends on it), and a bug where the branch is chosen from CURRENT state: one Page Up press started the melody on poll 1 and, 33 ms later, took the it's-already-playing branch. A `wait()` throttle only narrows the window — 200 ms still sits inside an 80–200 ms keypress — and the semantic being implemented is "press AGAIN", which is the edge. Sample once per frame above the dispatch chain, act on the up→down transition, and keep the level test for chain ordering so a held key still masks the keys below it. 2026-08-11: reported as "the STA sometimes won't replay from the head"; the fix is `_pageup_was_down` in `app.py::_handle_input_main`, locked by T1 `test_playback.py`.
- **A placeholder that means "legitimately empty" must never be reused for "failed".** An empty-state token is a well-formed answer, so a failure wearing it looks normal — and recolouring it does not help, because the glyph is the thing being read. The band drew `--` for both "no speed limit is posted here", true for a whole Keihin drive, and "the read was refused", so neither the user nor the author could tell a broken drive from a working one. `?` for tried-and-failed, `--` kept honest. 2026-09-12, author: *"'--' was too informative"* — it presents as a confident reading. **Before changing how an element renders in a NEW state, read what the doc already says about its existing ones**: the same change dropped the unit beside `?`, which `docs/APP.md` had made static chrome years earlier, and the author caught it rather than the doc.
- **Two saturated colours do not separate at small AA-off px on near-black — one side has to go dim.** Amber against red at 18px was rendered side by side and read as the same band, so a distinction the author had explicitly asked for was invisible in the thing built to carry it. Dim against one saturated row separates, and it usually says the truer thing anyway: on the band a row that stood down because another read failed is *not* faulty, so quiet-beside-one-loud reads as "one fault, three consequences" where three bright rows read as three faults. Render the two cases adjacent before believing any small-px colour distinction (`principles.md` § "Draw spatial structure, prose loses").
- **A fail-soft handler on a PER-FRAME call reports once and then suppresses — never a blanket `except: pass`.** The thing a silent swallow hides is usually not the failure it was written for; it is a bug in the guarded call itself, and the guard then never runs and never says so. 2026-08-23: the bell window's topmost re-pin was written `except Exception: pass` because it runs 15×/s, and a missing `_SWP_NOMOVE` constant made every call raise `NameError` into it. The window silently stopped being always-on-top and nothing anywhere reported it; the symptom looked like SDL dropping the style. A one-shot flag (`self._pin_failed`) keeps the console quiet and still makes the first failure visible. A guard that has never spoken has not been shown to run, which is [principles.md § "A measurement is a claim…"](principles.md)'s "a check that has never been observed to fail has not been shown to work" applied to a handler.
- **User-facing labels use public language, not internal vocabulary.** When an internal or debug surface becomes user-visible, and this project ships lightly-public, translate layer and wire jargon into words a non-developer reads. The 2026-05-31 debug-panel pass: `badge:` → `state:`, `Auto-fired` → `Auto-played`, the internal fire-names `departure` / `at-station` → `Next stop` / `At station`, `Game Sync` → `Auto-PA`. Keep an unlocalized technical term such as `OCR` only where the user has already seeded it with end users, and annotate that exception inline. *"this debug panel was our internal jargons, I need to carry this out in a somewhat publically understandable format."*
- **An internal status flag surfaces as the tier the user gets, never as our process.** `ResolutionProfile.verified` is a real distinction worth showing, but "已實機驗證 1080P / 1440P / 4K" tells the reader what we did. The OCR consent panel pairs a "tested on …" line with an "other … also work, but are not yet tested" line: the same flag, framed as what they can expect. Read `data/translations_app.json` for the current copy, since the resolution list moves as drives land. 2026-07-26: *"language is cringe about resolution support"*, then *"split into actual support and 'extended support'"*. The correction was framing rather than omission, and dropping the distinction entirely was also wrong.
- **TIMS button interaction model: one graphics signal per logical condition, uniform across every setup screen.** Built flow-wide 2026-07-15.
  - **Yellow press flash** (`press_transition` `state="pressed"`) means registered, on every clickable button. A locked or inactive button gets no yellow, since its click no-ops on the same precondition that silvers it.
  - **Loading beat** (`press_transition` with `blank_ms>0`, blanking below the band) is for navigating buttons only: opening a screen, launching the sim, committing and returning. In-place actions such as steppers use `blank_ms=0`.
  - **Flash white** (`state="waiting"`, time-phase toggle) means actionable next or current: a gated action now ready (OCR起動 when committed, 設定 when changed, consent OK when scrolled), or the current selection.
  - **Silver** (`chrome.DISABLED`) means inactive; see the next bullet.
  - **Selection idiom:** a picked cell shows steady yellow when a separate confirm button (設定) carries the proceed flash, and flashes when the click itself commits, as on model-select where there is no confirm.
  - **Non-button exemption:** the model governs TIMS bevel buttons. Click targets whose result is itself the acknowledgment are exempt and were reviewed as such: the home version tag (the browser opens), the tutorial progress dots (the lit dot advances), the tutorial LCD click-to-seek (the LCD jumps). Don't re-flag these.
- **Disabled / unavailable TIMS button = a desaturated SILVER palette, not a dark scrim.** A grayed bevel button renders via the silver overlay — NOT a translucent dark scrim on the blue button (a scrim reads "shadowed / pressed," not "disabled"; silver reads inactive, matching the IRL TIMS 番台選択 grayed entries). The ONE canonical silver is **`chrome.DISABLED`** (a color-overlay dict — face/bezel/ink — spread `{**BASE, **chrome.DISABLED}` and drawn `state="normal"`); centralized 2026-07-15 when the grey spread past one screen. Everything inactive uses it: model-roadmap, consent-OK-locked, tutorial-disabled (TIMS + classic `tutorial.py`), launch-locked, at-bound steppers, inert band buttons, page-edge arrows. `_GRAY_T` / `_FOOT_T_GREY` retained as local aliases (`{**base, **chrome.DISABLED}`). First instance: `model_select._GRAY_T` (2026-06-28).
- **Grouped buttons share size AND design.** Buttons that read as a GROUP — positionally (same row / cluster / bar) OR functionally (a footer's 取消/明白, a stepper's −/＋) — must share one size and one design (preset). A group sizes to the WORST-CASE member (widest label + padding), shorter labels centering inside; don't size each to its own content and let them jitter. Instances (all 2026-07-06): route bottom bar `返回`/`設定` widths matched (was `返回` +8px); `列車型號` normalized to the OCR-cluster button size (`bw × bh`, same font) so the pa-page bottom row is uniform; the OCR launch cluster's 3 buttons already EQUAL by design; consent footer `取消`/`明白` equal. **Disabled state is NOT an exception** — a grayed member keeps the group's geometry, only the palette goes silver (see the disabled-button bullet). 2026-07-06: user — *"for all buttons that are supposedly grouped together (either positionally or functionally), they should share the same size and design."*
- **TIMS chrome style warehouse: shared vocabulary central, layout local.** Repeated design tokens live once in `tims/chrome.py`, shared by the `tims.setup` flow and the live in-drive OCR status band `tims/band.py`. Screens compose from it rather than re-deriving. `tims/widgets.py` holds the primitives (`draw_tims_button`, base `_TUNEABLES_TIMS_BUTTON`, `tims_button_size`); `tims/chrome.py` holds the vocabulary:
  - **PALETTE** colour constants (`BG`, `PANEL_BG`, `FRAME`, `GRID`, `INK`, `DIM`, `CYAN`, `CODE_INK`, `AMBER`, `GREEN`). A shared colour is one value, and drift is the bug centralizing fixed: they had forked to near-black `(8,10,14)` against `(10,13,18)`, ink `(236,241,246)` against `(232,238,245)`, light-slate `(150,162,176)` against `(150,164,178)`.
  - **Button presets by role**, as plain dicts: `BTN_BAR` justify-split for two-character bottom-bar buttons (返回/設定/取消/明白), `BTN_LABEL` center-natural for page buttons, `BTN_ACTION` for home cards, `BTN_STEP` for steppers. Plain dicts rather than a dataclass, so the per-screen `{**PRESET, "text_align": …}` spread still works.
  - **`FONT_PX`** role sizes for recurring cases only, and **`DISABLED`**, the one silver inactive-button overlay.
  - One-off or model-specific dicts, one-off colours, and per-screen layout geometry stay local. The palette migrated big-bang, since otherwise drift persists; buttons and fonts convert lazily as touched. No screen registry and no `preset()` helper, both judged over-engineered. (2026-07-06.)
- **AA-off lowres text renderers don't handle `\n` — split hard newlines FIRST.** `draw_lowres_text` / the mixed-text wrappers (`tutorial._wrap_lines` / `_render_mixed`) treat `\n` as an ordinary character; the Noto face has no glyph for it, so an embedded newline renders as a **tofu box** (and the intended line break is lost). When a body string carries explicit `\n` (multi-line i18n, e.g. the tutorial recap quick-reference), split on `\n` in the caller and wrap each hard line separately; `\n\n` → a blank-line gap. 2026-07-11: the vertical tutorial's step-8 recap rendered 3 tofu boxes where its newlines were.
- **Fixed-column multi-locale label strip → wrap EN, don't grow the column.** When a horizontal label strip has a FIXED per-item column budget (N labels across a fixed width — e.g. the tutorial progress strip's 8 phases across 730px), EN labels overflow the column where compact CJK fits on one line. Wrap the overflowing label to ≤2 lines (break on spaces AND hyphens; a single unsplittable token — a short CJK run — stays one line) rather than shrink the font or narrow the gap. If the strip's height feeds a DERIVED window height (`SCREEN_H = … + STRIP_H + PANEL_H`), bumping the strip to fit 2 lines just grows the window — the panel is untouched. Measure the wrapped widths against the column empirically (don't eyeball). First instance: `tims/setup/tutorial_basic._wrap_phase_label` (2026-07-11). Where the width is not fixed, the multi-locale rule under Tooling above grows it to the active-locale label instead.
