## Session: E235-0 chevron animation restructure + slot_w spacing + font-path migration (PM late)

Continuation of earlier PM-evening chevron work. Three lines of refinement landed.

**Animation timeline restructured to no-overlap two-chev march.** Earlier-PM design had `phase_offset_s = sweep_duration_s`, so chev2 spawns at A simultaneously with chev1 starting fade-out at B (the "continuous arrow march" framing). User pushed back twice on rest length, then surfaced *"fades at B then suddenly flashes back"* — diagnosed as `_compute_chevron_animation_state` returning `[]` during the legitimate rest gap, which the dispatcher in `show_stops` treated as the deferred-case signal (`if chevs:` branch) and fell back to a static full-alpha chev at curr_stop's near-circle position. Two structural changes: (a) `phase_offset = sweep + fade_out + rest`, `cycle = 2 * phase_offset` — chev2 only spawns at A AFTER chev1 finishes fading out; `rest_s` now directly = empty visible gap; (b) return type `Optional[List]` distinguishes deferred (None → static fallback) from rest-frame ([] → draw nothing). Also added `fade_out_power = 2` (accelerating fade-out, slow-then-fast).

**Cross-row chevron behavior: no animation over the curve.** User clarified IRL: at curve transitions (JY01→JY02 right curve, JY16→JY17 left curve) chev does NOT animate across. Instead, pretend prev is one slot adjacent to curr on the same row, in the direction opposite travel (top R→L → phantom right of curr; bottom L→R → phantom left). Implementation: cross-row branch in `_compute_chevron_animation_state` synthesizes phantom_pos at `curr_pos.x ± self.slot_w` instead of returning None.

**IRL spacing rule: shared slot_w.** Bottom row has 14 stations (JY26 missing pre-2020) vs top row's 15. Prior code distributed each row evenly within the same straight-section width → bottom got wider per-station pitch. User: *"the stations at the bottom use the same item spacing as the top row, then the extra spaces are distributed on the 2 sides on the bar."* Implemented: `slot_w = straight_w / max(top_n, bottom_n)`; both rows use that pitch; shorter row centers within straight_w (slack split equally). `self.slot_w` exposed for chevron-cross-row reuse.

**Vibe-check + /review+fix sweep.** /vibe-check on the four train-model LCD files surfaced: unused `S_HEIGHT` import (sibling drift in both models), stale "(pentagon is static)" docstring + bare `"fonts/X.otf"` paths (deployment-frame violation per `critical_lessons.md` 2026-05-05 — e235_0 fork inherited the violation faithfully from e235_1000 along with the visual primitives), dead `_last_curr_stop` state, `hit_test` interface stub. Fixed all five across all four files (~41 font sites). /review+fix caught a Black formatting violation from the bulk `replace_all` (`,N)` no space — pre-commit would have rejected) and flagged that e235_1000 EnglishDisplay single-line dest didn't follow today's e235_0 LEFT-align change → deferred to TODO per `principles.md § Scope fidelity` since user-stated scope was e235_0 only.

**Codification: deployment-frame primitives complement visual primitives in sibling-fork inheritance.** The earlier "Forking a sibling-model renderer" rule covered visual primitives (copy verbatim, encode pixel-tuned constants).
