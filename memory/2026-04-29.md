## 2. Lower LCD `_calculate_layout` — uniform 14-per-line rule

Removed the `>17 or even / else 17` branch that special-cased 17-stop odd routes (concretely: keiyo/780Y_1510Y) to render single-row of 17. The IRL E235-1000 PIDS is 14-per-line; the 17-fallback was a one-time concession to keep keiyo single-row even though that's not how E235-1000 actually displays.

With the per-train-model architecture in place + best-effort policy for out-of-spec routes (keiyo isn't an E235-1000 line IRL), the cap can now be applied uniformly. New rule:

```python
if num_stops <= STOPS_PER_LINE:        # ≤14 → 1 row
    self.per_line = num_stops
else:                                   # >14 → 2 rows, capped at 14
    self.per_line = min(STOPS_PER_LINE, math.ceil(num_stops / 2))
```

Visible regression: keiyo 17 → 9+8 wrap (was 1×17). Accepted as the single-route cost of consolidating on the IRL rule. All other shipped routes pixel-identical because they were already at the 14-cap or matched the new ceil(n/2) rule by coincidence (sobu 19→10+9, tokaido 21→11+10, saikyo 24→12+12, nambu 26→13+13, chuo 32→14+14 with flip, keihin 46→14+14 with flip).

DISPLAY.md table updated to the cleaner three-row form (≤14 / 15–28 / >28).

## 3. `pre_stops` — through-service prefix on the lower LCD

The headline feature. JR East trains regularly through-run between lines; the canonical example is Sōbu/1217F, which physically runs Yokosuka Line 久里浜→東京 then continues as Sōbu Rapid 東京→成田空港. IRL the LCD displays the combined journey with the Yokosuka portion dim/passed.

### Schema

New optional `pre_stops` field at the route level:

```json
{
  "pre_stops": [
    {"name": "久里浜", "sta_code": "JO01"},
    {"name": "衣笠",   "sta_code": "JO02"},
    ...
    {"name": "新橋",   "sta_code": "JO18"}
  ],
  "stops": [
    {"name": "東京", "pa": [], "time": 0, "sta_code": "JO19", ...},
    ...
  ]
}
```

Each pre-stop has only `name` + `sta_code`. No `pa` / `pa_at_station` / `sta` / `sta_cut` / `time` — the simulator never advances into pre_stops, so those fields would be ignored anyway. Documented as "forbidden" to make intent explicit.

Sobu/1217F populated with all 18 Yokosuka Line stations (JO01..JO18).

### Implementation

Sim code (`app.py`, `audio.py`, `upper_lcd.py`) **untouched**. `state.curr_stop` still indexes `stops[]` (sim truth). All shifting happens in the lower-LCD renderers:

- `JapaneseDisplay` and `JapaneseEightStationDisplay` build `self.display_stops = self.pre_stops + self.stops` and `self.display_offset = len(self.pre_stops)` at init.
- `_calculate_layout` sizes against `len(self.display_stops)`. Circular detection stays on `self.stops` only (pre_stops can't make a route circular).
- `show_stops` in both renderers computes `curr_stop_disp = state.curr_stop + self.display_offset` (and same for cursor_pos) at the top, then passes display-shifted indices to all helpers (`draw_marks` / `draw_ptr` / `draw_times`). The helpers operate purely in display-index space.
- Pentagon boot fallback `curr_stop == 0` updated to `curr_stop == self.display_offset` — fires at the active route's first cell. For routes without pre_stops (display_offset=0) it's identical to the original.
- `text_color` boot exception `gi == 0` likewise updated to `gi == self.display_offset`.
- Pre-route cells naturally render in `INACTIVE_COLOR` because `cursor_pos_disp ≥ display_offset` always, so any pre cell has `cursor_pos > gi` — falls outside the active range.

### Window-flip — the design wrinkle

Native long routes (chuo, keihin) use **early-flip** in `_get_stops_list_disp`: when `remaining < STOPS_QUANTITY`, window flips from `[0:28]` to `[-28:]`. This shows "end approaching" once the train is in the latter half.

Pre_stops routes break this. For Sobu/1217F at boot: 18 pre + 19 active = 37 cells, train at display idx 18 (Tokyo), `remaining = 19 < 28` → standard logic flips immediately, hiding Kurihama..Tokyo from view. User observed this and corrected: "i want the fullroute display to show from kurihama".

Fix: dual flip-rule, branched on whether `pre_stops` is non-empty:

```python
if self.pre_stops:
    # late-flip: keep window pinned at start until train scrolls off the right edge
    should_flip = curr_stop > self.STOPS_QUANTITY - 1
else:
    # early-flip: standard "approaching end" trigger (preserved for chuo/keihin)
    remaining = len(self.display_stops) - curr_stop
    should_flip = 0 < remaining < self.STOPS_QUANTITY
```

Same final shape (one-shot flip from `[0:28]` to `[-28:]`), different trigger. Late-flip keeps the through-service prefix visible at boot; the flip fires later when the train would actually scroll off the right edge of the first window.

Verified: keihin/chuo unchanged, sobu/1217F now shows 久里浜..千葉 at boot with row 1 = 久里浜..新川崎 (14 dim) and row 2 = 武蔵小杉..新橋 (4 dim) + 東京 pentagon + 新日本橋..千葉 (10 active).
