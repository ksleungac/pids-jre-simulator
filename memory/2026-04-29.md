### Click-jump MVP — App-state side shipped on the lower LCD

**Contract:** click on station cell → `app.jump_to_stop(target)` + `audio.pause()` (lifted into `jump_to_stop` itself) → result is `STOPPING@target`.

**Hit-test caching pattern:** both renderers stash their last-rendered window as `self._last_window` in `show_stops`. `hit_test` reads from there, ensuring (a) click geometry matches what was actually drawn, and (b) avoids re-running `_get_stops_list_disp` (which has the `continuity[2]` mutation side-effect — would re-mutate on every hover frame otherwise).

**Filter placement:**
- **Pre_stops** (display_index < display_offset) → renderer's `hit_test` returns `None`. Lives in renderer because pre_stops is a property of the displayed content.
- **Past-dest** (sim_idx > `dest_stop_idx` on non-circular routes — Keihin 727B's 磯子→大船 reference tail) → click handler's `_click_target`. Lives there because `dest_stop_idx` is on `PASimulator`, not the renderer.

**`audio.pause()` lifted into `jump_to_stop`.** WIP previously said "callers should `audio.pause()` before invoking" but the cleaner contract is "`jump_to_stop` self-pauses, callers don't have to." Single ownership point covers click-jump, preview ←/→, and any future caller. `_SilentAudio` no-op makes preview-mode pausing harmless.

**Hover cursor:** `_update_hover_cursor` ticks every frame; same predicate as click filter (via shared `_click_target` helper) so hover-feedback exactly matches click behavior.

## Session: Late evening — Chrome i18n foundation: language picker + setup translation + line badge + theme

### Why now

User flagged future need for OOBE first-time start guide; before building that, needed an i18n foundation since OOBE will be multi-screen text-heavy and English-only would exclude HK/CN railfans at the moment of first impression. Ship i18n + chrome refresh + line badge as the foundation; OOBE follows.

### `i18n.py` module structure

Three concerns colocated: settings persistence (`settings.json` next to exe, frozen-aware path, gitignored), locale detection (`locale.getdefaultlocale()` → `zh_HK` / `zh_CN` / `en`), translation lookup (`init(lang)` loads `data/translations_app.json` once; `t(key, **fmt)` returns localized + EN fallback + key fallback).

### Two pygame font discoveries (CRITICAL — would bite again)

1. **pygame `SysFont` comma-list is INSTALLATION fallback, NOT glyph-level fallback.** Initially tried `pygame.font.SysFont("arial,microsoftjhenghei,microsoftyahei", size)` expecting Arial for Latin chars + JhengHei for CJK. **Wrong.** SysFont picks the FIRST installed font from the list and uses it for everything. Missing glyphs render as `.notdef`. Fix: use a single CJK font per language (JhengHei or YaHei) — both include Latin glyphs, "English" labels render fine through them, CJK chars also work. Documented inline at `i18n.py:118-131`.

2. **`font.metrics()` LIES about `.notdef` substitution.** Returns non-None for all four arrows `↑↓→←` in HelveticaNeue-Bold even though they all render as identical 12×29 surfaces with identical bounding boxes (the classic `.notdef` tofu signature). Honest probe: `font.render(c).get_bounding_rect()` and check for identical-bbox signatures across known-missing chars vs varying bboxes for real glyphs. Practical implication: any Unicode arrow chars in EN-mode chrome strings render as boxes with HelveticaNeue. Workaround: words ("Up/Down" not "↑↓", "Bound for" not "→").

### Line badge per route row

Re-used `displays/utils.draw_station_code_badge`. Relaxed regex from `(\d+)` to `(\d*)` so letters-only "line marker" mode works. Line code = first 2 chars of any stop's `sta_code` (e.g. `JO`, `JK`, `JC`); routes without sta_code (joban) skip the badge AND `_draw_line_badge` returns `x` instead of `x + badge_w` (no phantom gap).

### `preview_chrome.py` caught EN-mode tofu bug on first run

Line 2 with untranslated kanji rendered as boxes with HelveticaNeue. Without the previewer this would have shipped to user's eyeball-test. Added EN-mode CJK fallback for line 2: detect any CJK codepoint (`0x3000–0x9FFF`) → fall back to YaHei.

### 2-line vertical centering — formula not magic numbers

Previous fix used `+5` / `+22` magic offsets tuned for one font's metrics — broke when fonts changed (bold CJK runs taller than the previous medium ShinGo). New approach: pre-render both lines, compute `content_h = line1_h + inter_gap + line2_h`, then `top_pad = (row_height - content_h) // 2`. Works regardless of single-pass vs two-pass line 1, regardless of which font picked.

## Session: Overnight — OOBE Tutorial: build + vibe-pass

Built the full 9-step tutorial in two phases: implementation (3 review cycles to converge), then a long vibe-pass driven by user feedback on visuals + state-machine corner cases.

### Latent bug fixed by state-jump convention

`_next_pa()` has an audio guard (`if not at_station and audio.is_playing(): return`). Before the convention, skip-step chains with audio still in flight from a previous step would silently no-op — state would lag behind. Pause-at-top-of-skip-step clears the guard so skip handlers calling `_next_pa` advance state cleanly. Convention applied at three sites: `_enter_step(n)`, `_skip_step()`, `_dispatch_action` ACT_CLICK. Plus `app.py:PASimulator.restore_state` switched `audio.stop()` → `audio.pause()` for consistency.

### `audio.py` — deleted `AudioPlayer.__del__`

The finalizer was calling `mixer.quit()` at GC time, which fired when the tutorial dropped its sim ref → torn down mixer the setup screen + main app were about to inherit. Removing `__del__` makes GC-safe sim drop possible. Cleanup is now caller-driven only (`PASimulator.cleanup()` on full app exit).

### Font swap — JhengHei → bundled OTFs

User: "fonts are too thin, almost not readable" (early), then "why are we using jhenghei? last time told you to just use helvetica or frutiguer for english? what?" SysFont JhengHei was tofu'ing Latin Extended-A glyphs — macron `ō` in `Kōzu` rendered as `□`. Bold variant dropped even more. Switched to bundled `HelveticaNeue-Roman/Medium/Bold.otf` (Latin, has macrons) + `ShinGoPr6N-Medium/Heavy.otf` (CJK).

`_render_mixed(text, latin_font, cjk_font, color)` splits per-codepoint (`_split_runs` yields `RUN_LATIN | RUN_CJK | RUN_KEYCAP`) and concatenates with baseline alignment via `font.get_ascent()`. `_measure_mixed` mirrors for word-wrap.
