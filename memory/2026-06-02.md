## Session: OCR disclaimer — trigger-timing journey diagram + review+fix

Continued the disclaimer popup. Added a NEW section between the flowchart and the consent: a 報站觸發時機 ("when auto-PA fires") journey diagram. Whole-page order is now intro → 工作原理 (4-step flowchart) → 報站觸發時機 (journey) → disclaimer.

WHY the section exists: the disclaimer says auto-PA "sometimes doesn't work normally," but the user has no model of what *normal* is — the 30 km/h departure trigger, the ~900 m arrival lead, the silent flip into at-station. The flowchart explains HOW the OCR reads the HUD; it never explained WHEN a PA actually fires. The journey diagram is that missing piece: a side-view Tokyo scene where a Suica-penguin E235 travels station A → B with the three trigger points labelled on the line.

Design decisions worth keeping:
- **Motion is a forward-only fade loop, NOT ping-pong.** Train runs A→B, fades out at B, fades back in at A. A directional train reversing reads wrong; fading conveys "next run" without implying backwards travel. Period 7000 ms.
- **Z-order (back→front): scenery (Fuji / skyline / Skytree / Tower) → station buildings → rail → trigger markers → penguin frontmost.** Penguin never clipped; everything scaled relative to the oversized Suica mascot.
- **Daytime palette on the dark (42,46,58) bg — contrast comes from lightness, not lit windows.** An earlier night-city pass with lit windows was a wrong turn; user wanted daytime with correct contrast.
- **Trigger labels: name + condition stacked at top; station names (車站A/B) at bottom.** Consistent "what fires" / "which station" split.

Wording locked: project term is **報站, not 廣播** (diff migrates the remaining 廣播 in this feature). ③ is **到達** — a *silent* state-change to at-station, not an announcement, so it carries no condition label. ①② are content-named: 「下一站」報站 / 「即將到達」報站.
