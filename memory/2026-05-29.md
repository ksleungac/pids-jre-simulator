**Update-hint feature (next release).** Design evolved under pushback: started with a hand-maintained `constants.VERSION` + a pre-commit sync sensor → user flagged the strangeness (manual bump, 3-way drift). Switched to reading the version the build already embeds in the exe's PE metadata via new `app_paths.app_version()` (win32api GetFileVersionInfo; None in dev → feature dormant). Key finding: uv REQUIRES a static `[project].version` and `dynamic=["version"]` forces uv into package/build mode (breaks `uv run`) — so pyproject keeps a standalone static version, decoupled (packaging-only). `update_check.py` is fail-silent by contract (offline/SSL/rate-limit/malformed → no hint, never raises), GET-only, certifi-routed SSL for the frozen exe. Hint = slate pill + green dot top-left on setup screen, mirroring the tutorial pill; clickable → release page. Tested via a throwaway 0.5.3 exe: PE read + live GitHub fetch + hint render + click all confirmed in the frozen build. review+fix: 1 cycle, 1 warning (stale docstring) fixed.
