## Session (eve): Upper-LCD clip-rect refactor

User opened with "would TSX/JS/CSS be better than pygame?" — distribution determinism + native audio/OCR coupling rule it out; transfer-info pain is the IRL-mimicking layout algorithm itself, not pygame's fault. That reframed the question to: *what about the clear-rect bookkeeping, then?*

Walked through patterns and walked back the over-built ones. Sketched an instrumented-region framework with overflow warnings + state-sweep harness; user pushed "think more potential problems"; framework collapsed under honest stress-test (font.size() lies, exhaustive enumeration is its own project, intentional-overlap exceptions, dynamic regions don't fit static manifest, bypass paths). Settled on the minimal version: `set_clip` context manager + per-region rect manifest. Each region's draw method wraps in `with clip(...)` — pygame drops out-of-clip pixels at the surface layer, structural guarantee against bleed.
