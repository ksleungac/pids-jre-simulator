## Session: Calibration editor future + two-tier tuning model

Strategic planning session on the calibration-editor branch. No code changes; WIP doc updates only.

Started by reviewing E235-0 5-station arc problem: circle-arc approach on master (curve_cx/cy/radius) can't match IRL Yamanote curvature, and Catmull-Rom drag handles (branch Phase 2) can't encode the precision of a hand-drawn curve regardless of point count or smoothing passes. Fundamental issue: N waypoints = lossy compression of what the user wants to draw.

Resolution: **mask PNG approach**. User draws arc shape in Photoshop (white-on-transparent), bakes route color at `__init__` via `BLEND_RGBA_MULT` — one bake, zero per-frame allocation, exact shape preserved, color problem solved. Catmull-Rom arc machinery retired.

Broader calibration editor discussion led to two-tier model:
- **Tier 1** (simple elements: positions, sizes, offsets) → `_TUNEABLES_*` + editor sidebar. Universal convention.
- **Tier 2** (complex geometry: non-parametric curves, shaped bands) → Photoshop → mask PNG. Case-by-case.

For the editor to become the standard for future train models (E233-0), 5 pillars must land:
1. Code standard in `conventions.md` (what makes a module editor-compatible)
2. Skill documenting the workflow
3. Editor on master (cherry-pick from branch, remove dead Catmull-Rom)
4. Lint gate (flag magic numbers outside `_TUNEABLES_*` dicts)
5. New-model skeleton

**Route A chosen**: E235-0 is the graduation vehicle — complete E235-0 (5-station mask PNG + remaining upper/lower elements wired), then port editor to master. E233-0 inherits fully proven framework.

All decisions written into `WIP_calibration_editor.md` on `feat/calibration-editor` branch.

## Session: Click-jump re-anchor (Layer 1 → Layer 2) for the auto-driver

Picked auto-input entry-point flow as the biggest reliability gap (per WIP_autodriver.md). Tackled click-jump first — toggle-ON deferred as lower-frequency (user doesn't toggle on/off mid-drive often).

**Problem state:** `jump_to_stop` puts App (Layer 1) in STOPPING@target and resets App state, but the AutoDriver's `_segment_start_stop` + Layer 2 flags are untouched. Result: every fire silently skips the `curr != _segment_start_stop` / `curr != expected` guards — driver effectively dead for the rest of the segment.

**Design (settled with user in layer vocabulary):** click-jump is **Layer 1 authoritative**. Re-anchor Layer 2 to mirror it — `_segment_start_stop=target`, `arrival_observed=departure_observed=False`, `at_station_observed=True` (suppress FIRE_AT_STATION), `prev_badge="STOPPED"`. Layer 3 then derives as IDLE. Scope locked: **parked case only**; mid-transit click-jump (Layer 3 driving) deferred — needs the silent-advance alignment rule, same machinery as toggle-ON.

**Detection mechanism fork:** chose explicit single-shot signal (`PASimulator.click_jump_pending`, set in `_handle_lcd_click`, consumed at top of capture loop) over the WIP doc's curr_stop-polling. Polling has to disambiguate the driver's own auto-advances from user clicks; the flag is unambiguous and matches the project's single-shot convention. No coverage loss — manual-PageDown drift (the third entry-point trigger) is already absorbed by the existing mismatch-skip.

**Gap caught in review:** `prev_speed` not reset → stale `prev_speed ∈ [0,29]` + a transient parked-platform speed misread ≥30 could satisfy `prev_speed<30<=speed` on the first post-jump cycle and fire a phantom departure (the `curr==segment_start` guard passes after re-anchor, so it wouldn't be caught downstream). Fix: `prev_speed=None` — disables the crossing test for exactly one cycle, self-heals next read. Verified the real departure still fires.

Consume placed before the OCR grab so `prev_badge="STOPPED"` is the baseline for the same cycle's `detector.update`. Print uses ASCII `->` not `→` (cp1252 console would crash on the arrow, caught by the loop's try/except but firing every cycle).

Validated with 3 isolated detector traces (no live game needed): re-anchor outcome, stable-park, departure-from-re-anchored-position; plus the spurious-departure-suppressed trace. User then live-drive validated.

Pyright flags `_reanchor_to_app` as unknown attribute — false positive (stale incremental analysis on the long `_run`); AST confirms it's a proper AutoDriver method.
