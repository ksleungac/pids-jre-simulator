## Session: E235-0 Yamanote sub-series scaffold + circular full-route renderer

Forked the upper LCD from E235-1000 (train-type cell removed; Yamanote runs single service type IRL — no need for a Local/Rapid/etc. cell). Built a brand-new circular full-route renderer for the lower LCD: rounded-rect track (NOT ellipse), JY-code-based row mapping (bottom row JY17→JY30→JY01 left-to-right inner-loop, top row JY02→JY16 right-to-left), breath-animated pentagon at the active stop, chevron arrow when between stations. When a non-Yamanote route is loaded into E235-0, falls back to E235-1000's linear renderer via subclass override.

Key shape decisions:

- **One canonical trigger.** `LowerDisplay` dispatches the circular renderer only when `route_name == "山手線"`. User pushed back on speculative future-proofing for "any circular line" — Yamanote is the only IRL circular line in scope, hardcode is fine.
- **Copy primitives, don't reinvent.** When the pentagon / dot / chevron / time-circle had to land in the new module, the user explicitly said "I am fine with duplication code but you at least please copy from, don't make one yourself." Visual-fidelity primitives encode pixel-tuned constants from prior iteration rounds (e.g. pentagon's `rect_half_w_back=21, rect_half_w_apex=20`); rolling a fresh version loses that calibration silently. Codified.
- **Pentagon breath animation.** Triangle wave (constant velocity, instant reversal at peaks — no "rest" feel), 1.2s period, uniform XY scale toward `(cx, cy)`. Halo polygons stay at max bbox so the red breathes inside a fixed-size halo. User iterated several times on the feel before the triangle wave was right.

Visual iteration churn was high (~26 versions of the route-bar render). The thrash signal: I kept reading the rendered PNG after each user-requested tweak. User: "u no need to read the png, this is slowing you down." Codified — when the user is in the loop providing feedback, they're the eye; reading the PNG adds latency without signal.

## Side-thread 2: Boot-frame `current_time` race + cycler-lock for previews

`preview_display.py --lower-view full` was opening in 8-station view despite the flag. Two bugs surfaced:

1. `app.py:run()` boot draw used default `current_time=0.0` for `lower.draw()`. That initialized the view-cycler's `_slot_start` to 0.0; the first main-loop tick (`current_time=time.time()`) then saw a huge delta and immediately advanced the slot. Fixed by passing `time.time()` to the boot draw. Anchored as a `# CONTRACT:` block at the boot-draw site so it survives future edits.
2. `--lower-view` only set the initial slot but the cycler kept ticking. Monkey-patched `_tick_cycle` and `_handle_at_station_edge` to no-ops in preview-only mode. Logged as a deferred review finding (lambda fragility — silently rots if those methods gain a parameter).
