## Session: SysFont release-build crash hotfix (PM)

User reported a real-user instant-crash on app launch. Suspected SysFont. Confirmed: the `b0a52a5` chrome refactor (i18n foundation) had re-introduced `pygame.font.SysFont()` into the launch path via `i18n.font_named()` (called by `font_for_lang` for zh_HK / zh_CN) and `tutorial._font_cjk` (for zh_CN). On Chinese-locale Windows, SysFont's registry walk raises `TypeError: expected str, bytes or os.PathLike object, not int` — exact replay of the 2026-03-14 crash mode. The picker fires the SysFont call **even for English-locale users on first launch** because it draws all three language rows in their own fonts; a Chinese-locale user with a fresh install was hitting the failing code path before reaching the picker UI.

Fix: routed all three SUPPORTED_LANGS through bundled OTFs. zh_HK uses ShinGoPr6N (JIS overlap covers Traditional Chinese). zh_CN gets a newly-bundled Noto Sans CJK SC (~33 MB for Regular + Bold; required for Simplified-specific glyphs that ShinGoPr6N tofus). Replaced i18n's `_LANG_CHROME_SYSFONT` dict + `font_named()` helper with a `_LANG_CHROME_FONT` mapping `{lang: (regular, bold)}` and rewrote `font_for_lang` to file-load only via `app_paths.project_root() / "fonts" / fname`. Tutorial's `_font_cjk` zh_CN branch now routes through the same. `font_named()` deleted (was the SysFont primitive; no callers after the fix). 3 cycles of `/review+fix` — cycle 1 found 2 stale-comment warnings I'd missed in my own sweep (CLAUDE.md table description + tutorial.py phase-keys comment), cycle 2 found the LanguagePicker docstring's "YaHei 24pt" reference (calibration anchor preserved with a "ratio was empirical against YaHei; re-eyeball if uneven" note), cycle 3 clean.

### Behavioral failure: SysFont site dismissed as "by design"

When user first asked "scan the repo, see if anywhere didn't use the local font," I found `i18n.font_named()`'s SysFont call but classified it as "Production runtime — by design (one site)" citing only the i18n.py docstring saying *"Windows ships YaHei… acceptable since the project's primary distribution is Windows."* The CONTRACT block at `displays/train_models/e235_1000/upper_lcd.py:144` — explicitly saying *"load fonts from file paths only — never pygame.font.SysFont() — SysFont scans the Windows font registry, which fails on Chinese/Japanese"* — was IN THE SAME GREP OUTPUT and went unread. The 2026-03-14 memory entry documenting the exact crash mode was one grep away.

Only after the user said "user reported instant crash on launch... I thought something todo with the sysfonts again" did I cross-check memory + CONTRACT and confirm the regression. User: *"yes but why did you answer me no where uses sysfont?"*

Same pathology as the 2026-05-05 reviewer who defended `i18n.app_root`'s `_MEIPASS` as "intentional semantics" by reasoning from generic PyInstaller mythology rather than checking THIS project's build script. Different substrate (OS-specifics vs PyInstaller mechanism), same shape: cached/local docstring framing accepted as authoritative; canonical rule corpus sat in context, unconsulted. The load-bearing phrase "by design / not a bug" was the smell — same as "intentional / standard / leave it alone" called out in the existing principle.

Codified as recurrence evidence in `principles.md § "Verify deployment-frame and external-runtime semantics from primary source"`. The principle's trigger heuristics already cover OS specifics; the addition is a 2026-05-07 evidence paragraph plus the user-quote snippet.
