**OCR consent + settings screen (`ocr_setting.py`).** New TIMS screen, ported from legacy

remaining piece (deferred). Details in `WIP_setup_redesign.md § OCR consent + settings screen`.

**TIMS chrome style warehouse.** User: *"i don't want to go through these kind of standard styling again
and again … a button's preset or warehouse"* — the standard vocabulary (buttons, palette, page code+title)
was re-authored per screen. User asked to consult `/third-man` on the proposal (a new design-consult
pathway for the skill). The third-man KILLED two over-engineered parts (a screen registry + a `preset()`
helper) and caught the real bug: the palette had already **drifted** — near-black existed as `(8,10,14)`
*and* `(10,13,18)`, ink as `(236,241,246)` *and* `(232,238,245)`, `_BAR_T` ≡ `_FOOT_T` byte-for-byte. So
palette centralization is a *drift fix*, not just DRY — and must be big-bang, not lazy. Built PALETTE +
button role-presets (`BTN_BAR/LABEL/ACTION/STEP`) + `FONT_PX` in `chrome.py` (`widgets.py` keeps primitives);
migrated all 6 screens; smoke-tested each. The "no false uniformity" convention is about LAYOUT geometry,
which is orthogonal to shared design tokens — that's why the warehouse doesn't fight it.
