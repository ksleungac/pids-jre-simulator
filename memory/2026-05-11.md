## Session: caveman skill exploration → in-repo absorption (chat hook + 3 docs + 2 skills)

User asked about the "caveman" Claude Code skill (JuliusBrussee/caveman) — telegraphic-prose mode that compresses output by dropping articles + connective tissue. Initial test surface: same 6 comprehension questions answered identically on original vs caveman-full versions of DATA_FORMAT sections (18/18 match across 3 rounds of blind A/B with fresh-context Opus sub-agents). Caveman preserves comprehension on technical reference text where the structure carries meaning; lower compression ceiling (~10-15%) than the marketed 65-75% because the docs were already tight from EDIT-CONTRACT + distill-docs sweeps + user's English-style preferences.

Decided to absorb caveman selectively, not install the plugin. Three layers:

- Chat output → caveman-full default, codified in CLAUDE.md § Chat output style (new section).
- UserPromptSubmit hook → injects rule reminder every 5th turn (drift mitigation that upstream caveman lacks; caveman's "Persistence: Remains active even if uncertain" is prompt-text only).
- Docs → caveman the 3 reference docs (DATA_FORMAT / DISPLAY / AUTO_INPUT) one-off + Voice EDIT-CONTRACT lines so future entries follow.

Key design calls:

- Binary toggle (normal vs caveman-full), no intensity levels per user preference.
- Memory daily logs / commits / code / public READMEs out of scope — narrative continuity / git-style / different-audience reasons.
- principles.md / critical_lessons.md out of scope — rationale-corpus shape, decoupling risk for cross-time citation chains.
- DISPLAY_E235.md deferred (active E235-0 churn) → TODO.md.
- AUTO_INPUT.md rewrite line-count drop (736→507) was soft-wrap unwrap, not content loss — verified via 11 key-phrase grep checks (`always disambiguate by field name`, `STOPPED is canonical, never transient`, `cross-attribute hardening philosophy`, etc.). Kept unwrapped to normalize across the doc family (DATA_FORMAT / DISPLAY weren't soft-wrapped either).

Two drift incidents surfaced mid-session, both addressed:

1. After ~6 turns of explainer-mode answers I reverted to verbose normal-grammar, mistaking "multi-step explanation" for caveman's "Auto-Clarity Carve-Outs" trigger. Same wording as upstream caveman SKILL.md — it's a known weak phrase. Fix: tightened CLAUDE.md § Chat output style carve-out to "material-consequence ambiguity" with explicit "multi-reason explanations with no action consequence don't qualify" guard.
2. User noticed length drift before I did. Confirms the hook-as-anti-drift hypothesis but also shows the carve-out trigger was the actual leak, not the hook cadence (5-turn modulo is fine; the rule itself was fuzzy).

Authorship principle clarified mid-session: who-typed-it matters, not who-asked-it. User's prompts untouched; claude-authored artifacts get caveman applied per scope. Skills (claude-authored) qualify; applied to session-recap as calibration; propagation to other skills left lazy (each touched naturally when invoked).

EDIT-CONTRACT Voice rule + audit-skill carve-outs landed so convention propagates: write-time gate (Voice in each doc's EDIT-CONTRACT), audit-time carve-out (distill-docs Step 2 #4 exception + NOT-bloat list addition for voice mismatch), recap-time reminder (session-recap Step 3 voice-switch note).
