# 2026-04-23

## Station Code Badge — 3-Letter Code Extension

### What shipped
- **Badge renders optional JR East 3-letter code** (e.g. AKB, TYO) above the existing green-framed JY/03 square, matching the real E235-1000 Yamanote upper LCD. When a station has no 3-letter code, rendering is unchanged from before — the feature is purely additive.
- **`data/stations.json`** introduced as a new project-level data file for line-independent station metadata. Starts with `code_3` only; designed to grow (transfers, platforms, etc. later).
- **Yamanote `route.json`** backfilled with `sta_code` on all 30 stops (derived from existing audio filename suffixes; Takanawa Gateway JY26 correctly absent since this diagram predates the 2020 station opening).
- **Preview script** gained `--route yamanote` / `--route chuo/916H` support for testing with real data.

### Key decisions and the WHY

- **Separate `data/stations.json` from `data/translations.json`** — same key space (Japanese station name) but intentionally decoupled by concern. Translations = display text; stations = operational/physical metadata. Worth the sync burden because station metadata will grow significantly (transfers, platforms, coordinates). Asked user before deciding.
- **Station metadata is line-independent** — a station that appears on multiple JR lines has ONE entry. 秋葉原 (on Yamanote AND Keihin-Tohoku) gets one row with `code_3: AKB`.
- **Killed the `audio/[line]/stations.json` scaffolds** — 5 files with `{}` values that `app.py` never actually read. DATA_FORMAT.md's claim that they were the source of line-specific data was aspirational only.

### JR East 3-letter code catalog is FINITE
The code is not "for every station" — only **22 stations total** have one. Assignment rule: stations where 3+ JR East line systems converge, with two documented exceptions (浜松町, 高輪ゲートウェイ). **Do not hunt for codes on smaller stations** — they use 2-char katakana telegraph codes (電略), a separate internal system we don't store. Full catalog now lives in `data/stations.json`.

### Canonical reference: `_draw_station_code_badge`
This method is now the canonical example of the repo's UI patterns:
- Tuneable-params block at the top (geometry + `code_3_band_h`, `code_3_x_offset`, `code_3_y_offset`) — all downstream coordinates derive from it
- `get_bounding_rect()` centering so swapping fonts doesn't break alignment
- Conditional rendering branches on presence of a data field, keeping the "no metadata" path pixel-identical to the pre-feature behavior

### Gotchas discovered
- **Draw order regression risk**: prefix box and badge share x=222. Fix: badge renders LAST in `UpperDisplay.draw()`. Without this, the extended top band gets clipped by DARK_BG rects painted over it.
- **`ModeCycler` has `enabled`, NOT `paused`** — assigning to `paused` silently creates a new attribute `update()` never reads. Preview script hit this — the forced `--mode` would have un-frozen after the cycle interval.
- **Release build would have shipped visibly broken** if the review loop hadn't caught it: `NeueFrutigerWorld-Bold.otf` was missing from `build/SKILL.md`'s font list (hard crash), `data/stations.json` was missing from `release.ps1`'s explicit-copy list (silent degradation — no code_3 bands in distributed builds). Fixed both; release.ps1 now uses `Copy-Item data\*.json` glob so future data files auto-ship.
