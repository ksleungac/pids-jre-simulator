## Session: E235-0 5-station green band fill — smooth curve-following feathered reveal + ease-in

Parallel-session split: another Claude on TIMS chrome, this one on the E235-0 5-station band fill
animation. Stayed clear of the chrome files (setup.py / widgets.py / i18n.py / WIP_setup_redesign.md +
the untracked `_noto_*` / `_gothic_compare` font-eval scripts); touched only e235_0 display + its doc.

Two user asks, both about the green fill that sweeps over the band on slot-enter:

- **"smooth, not sharp green."** Root cause: the reveal erased the un-revealed half-plane with a hard
  `pygame.draw.polygon` (no AA) → a sharp diagonal green/gray cut. Fix: build a reveal MASK (white-with-
  alpha), ramp its alpha across the front, and multiply it into a copy of the green band via
  `BLEND_RGBA_MULT` (scales only the band's alpha; RGB green preserved since the mask's RGB is 255).
- **"front always diagonal to the curve path."** Reworked from a single fixed sweep angle
  (`_BAND_FILL_ANGLE`, removed) to **arc-length parameterization along the band centerline**. Precompute
  the centerline once in `__init__` (`_build_fill_centerline`): waypoints = retired `_TUNEABLES_ARC`
  p0/p6 end-caps bracketing the live markers m0–m4, densified via the existing
  `_build_catmull_rom_centerline` helper. Each animation frame stamps per-segment corridor quads
  perpendicular to the local tangent up to `front_s = progress * arc_len`, so the leading edge rotates to
  stay perpendicular to the band's local direction at every height.

Why these choices: markers m0–m4 are the live, rendered, on-band points (front tracks what's on screen);
p0/p6 supply the caps for full coverage. Corridor half-width (100) over-covers and is clipped by the
band PNG's own alpha, so it just needs to exceed the band's widest half-thickness. **Trailing** feather
(behind the front, not centered) so progress maps cleanly 0→nothing / 1→full and the leading edge is the
soft one.

Tuning (user is visual judge, live preview each round): feather 36→18 ("sharper, still has transition"),
timing linear→ease-in (`_BAND_FILL_EASE_POWER`=2.0 — "accelerate toward the end" = ease-in, slow start),
period 2.0→1.5s. Ease only redistributes speed within the window; total period is still `_BAND_FILL_DURATION`.

review+fix: 0 blocking. Fixed perf (hoisted the reveal surface to a reusable `_fill_reveal` field +
`_BAND_FILL_SAMPLES_PER_SEG` 80→40, feather verified still smooth) + a stale "band axis" comment +
doc/strokes nits. Deferred the `_TUNEABLES_ARC` split-personality (p0/p6 now read live from a dict
labeled "retired", whose p1–p5 + `_smooth_centerline` + `_ARC_STATION_SLOTS` are dead remnants) → folded
into the P5 calibration-editor cleanup item rather than scope-expanding the animation task.
