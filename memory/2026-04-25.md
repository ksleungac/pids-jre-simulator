- `--debug-grid` CLI flag in `preview_display.py` flips the module attr before construction.
- All ~13 `pygame.draw.rect(self.screen, DARK_BG, ...)` clear rects across Japanese/Furigana/EnglishDisplay + UpperDisplay migrated to `_bg("region")`.

- Caught a *design oversight*: English `draw_destination` had no clear rect at all, and Japanese/Furigana cleared only their narrow 150x35 box (not the suffix area below). Manifested as untinted patches in debug-grid mode.
- **Convention**: every changeable element clears its **full territory** as the first step of its draw method, via `_bg("region")`. Territory must accommodate the largest variant the element can render (single-line + 2-line + suffix), not just the current glyph footprint. All three mode renderers share the same territory per element.
- Dest unified across modes: `(0, 50, 180, UPPER_HEIGHT - 50)` everywhere. Suffix `font.render(text, True, fg, bg)` bg parameters also use `_bg("dest")` so they don't punch holes in the tint.
- train_type intentionally NOT in `_DEBUG_COLORS` — its WHITE_BG box is already visually distinct from every other region's tint. Falls through to `default=WHITE_BG`. Documented inline.
- Documented in `UPPER_DISPLAY_UPDATE.md` "Element Clear-Background Convention" section. NOT in `notes.md` — display-specific guidance lives in display docs (user redirected me on this).

### Region Map (per-train-model, in code)
- Comment block at the top of `upper_lcd.py`, co-located with `_DEBUG_COLORS`. Bounds + drawn-by + debug color for every region.
- Per-train-model rather than in markdown doc — different train models will have different layouts. `UPPER_DISPLAY_UPDATE.md` carries a one-line pointer to where the map lives.
- Authoritative bounds are still the inline tuneable params in each draw method; the table is descriptive (navigation aid). Drift risk mitigated by `--debug-grid` providing an out-of-band visual check.

### Containment principle (extension of clear-bg convention)
- Surfaced when debug-grid revealed "Narita Airport" line 1 caps at 44pt sitting in the BLUE prefix tint (i.e. drawn outside the station region). User: "ensure nothing ever drawn outside of its predefined grid."
- **Rule**: drawn pixels (glyphs, shapes, fills) must stay within the region's territory — not just the clear rect. If glyphs would overflow, either resize them down or expand the territory definition.
- Debug-grid is the visual check: a glyph rendered on top of a *neighboring* region's tint is a containment violation.

- Station's `_clear_rect` helper now clamps BOTH ends (top to band_bottom_y, bottom to UPPER_HEIGHT) for the same reason — the clear rect itself shouldn't leak into the lower display either.

# 2026-04-25 (very late) — Distilled framework: confinement, D1/D2, clear-rect-as-drawing

After all the back-and-forth tuning the 2-line station font (44 → 42 → 38 → back to 42 → settled), the conceptual framework that made everything click:

## The principle

Every region has a declared **confinement** (a rectangle). Anything the region draws — bg fill, glyph pixels, decorations — must visually stay inside that confinement. **Clear rect is not special; it's just one of the things drawn for the region**, same rule applies as for glyphs.

The user's framing that landed it: "we can imagine clear rect as a part of drawing glyphs, as long as nothing visually drawn out of confinement we are safe."

## Two compliance checks

Pygame font surfaces have **leading** — empty/transparent pixels above visible glyph caps. ~10–15px for big fonts. So:

- **D1 (surface check, cheap)**: `blit_y ≥ confinement.top`. Pure analytical. If passes → containment guaranteed (no pixel can render above blit_y by pygame's blit guarantee).
- **D2 (visible-pixel check, real)**: actual visible glyph caps land at y ≥ confinement.top. Requires probing or per-font knowledge of leading.

**D2 is the rule that ships.** D1 is a useful pre-check. **If D1 fails, that's a *signal to probe*, not auto-violation** — leading might absorb the overshoot.

The user's concern that drove this: "if I enforce D1, if 2 elements are very close to each other I won't be able to squash them very close." Right — D1 forces empty leading pixels into the spacing budget. For 78pt kanji with ~10–15px leading, strict D1 would forbid the IRL-accurate font size unnecessarily even though visible glyphs DO comply. D2 is the actual rule.

## Probing methodology gotcha (lesson learned the hard way)

When probing for containment violations, **isolate the region** — neighbors' glyphs in overlapping x-ranges easily masquerade as the target's. I (Claude) misread the prefix's "Now stopping at" text glyph pixels at x=315, y=22-24 as the station's "Narita Airport" line 1 caps and reported a false D2 violation at 42pt. The user pushed back: "how is 42 not compliant to containment principle??"

Fix: probe with a clean scenario. Either use the short "Next" prefix (x≤280, leaves x=302+ purely station territory), or probe at exclusive-x ranges where only the target paints (for station: x=522–570, x=650–686 between/around prefix and clock). Codified in visual-adjust SKILL.md.

## Audit results (E235-1000 upper, station element)

All 4 station modes' visible glyphs comply with D2 (caps at y≥35):
- Kanji 78pt: caps below y=35 via leading absorption
- Furigana 78pt: same
- English 1-line 75pt: same
- English 2-line 42pt: caps at y=37, 2px clear

Clear rects (post-fix): all 4 modes clamped to y≥35 via the same pattern as English's `_clear_rect`. Pre-fix, Kanji and Furigana had a 1px bg leak at y=34 (kanji `name_y = 117 - 78 - 5 = 34`). User: "the so called confinement isn't really anything..go with 1" → applied the clamp to JapaneseDisplay and FuriganaDisplay's `draw_station`.

## What got updated

- `upper_lcd.py` Region Map: station now `(302, 35, 384, 82)` — truthful for clear rects across all 4 modes
- `JapaneseDisplay.draw_station` and `FuriganaDisplay.draw_station`: now clamp clear rect to `band_bottom_y=35` and `UPPER_HEIGHT`, matching English
- `UPPER_DISPLAY_UPDATE.md` "Element Clear-Background Convention" section: rewritten with the unified principle, D1/D2 explanation, probing methodology, current state

- `.claude/skills/visual-adjust/SKILL.md` "Debug-grid mode" section: rewritten with D1/D2 framing and probing methodology gotcha (with the actual mistake I made as a cautionary example)
- `displays/train_models/e235_1000/upper_lcd.py` Region Map comment: clarified that "confinement" is the declared boundary for ALL drawings (clear rect AND glyphs), not just clear rects

## Durable insights for future-me

1. **One bound per region, one rule** — anything drawn must stay inside. Clear rect, glyphs, all the same.
2. **Pygame surfaces ≠ visible pixels** — leading absorbs surface overshoot. D1 surface check is conservative; D2 visible-pixel check is the truth.
3. **Pixel-perfect tuning requires D2** — accept D1 failures when leading absorbs, don't shrink fonts unnecessarily.
4. **Probe carefully** — isolate the region under test from neighbors that might paint in overlapping x-ranges. Use short-prefix scenarios or exclusive-x probes.
5. **Debug-grid is the unified verification tool** — region tints make all violations (bg leaks, glyph escapes) immediately visible at runtime. No theoretical reasoning required.

## Goal

## Iteration log (worth remembering)
1. Started with ascent-tight pitch + top_pad=12. Gave 12px gap under "for", but lines overlapped (line 2 caps on line 1 baseline → "p" descender of line 1 collided with line 2 caps).
2. User: "2 lines are too close". Switched to full-height pitch (`line_pitch = font.get_height()`). Inter-line gap restored, but vertical budget tightened.
3. User: "good 2 lines spacing now, now move it a bit higher still, 2~3 pixels?". Reduced top_pad 8 → 5.
4. Final: 24pt + full-height pitch + top_pad=5 fits within UPPER_HEIGHT cleanly, with comfortable inter-line spacing and acceptable gap under "for".

## Lesson
Three competing constraints in a tight vertical zone:
- Gap under "for" (top_pad)
- Inter-line gap (line_pitch — function of font size + leading)
- Fit within UPPER_HEIGHT (no descender overflow)

Can't max all three at the same font size. Trade-offs:
- Bigger font → less of either gap.
- Ascent pitch → tightest possible (zero descender-to-cap gap; OK only when line 1 has no descenders, or you accept the overlap).
- Full-height pitch → natural readable gap (font designer's intended leading), at the cost of vertical space.

Default to **full-height pitch** for readable text. Use ascent pitch only when:
- The element is a label-pair where overlap is OK (e.g. station big text with line 2 right-aligned far from line 1 horizontally), OR
- Vertical budget is genuinely too tight and the trade-off is justified.

- 1-PA mid-route stations → `{prev}-dep` (the PA covers "we just left X, next is Y")
- Terminus single PA → `{this}-arr`

**STA:** `{station}_{platform}_{song-id}.mp3`
- Underscore between fields, hyphens within. **Station first** (easier to scan when listing files)
- Only `station` is required; drop unknown parts with their separator
- Examples: `narita_3_soyokaze`, `narita_3` (song unknown), `shisui_gota-del-vient` (no platform), `yotsukaido_2` (song still unknown)

**Japanese-to-slug:** Hepburn romanization, macrons stripped, lowercase, hyphens for word boundaries. Same rule already used for station name slugs (東京 → `tokyo`, 越中島 → `etchujima`). Applies to song slugs (スイートコール → `suito-koru`, フラワーショップ → `furawa-shoppu`).

**`sta_cut`:** seconds from **START** of file (not end — the old AUDIO_SPLITTING_WORKFLOW.md was wrong). Computed as `cut_timestamp - start_timestamp`.

## Key decisions (don't re-derive)

1. **Audio file = atomic unit.** Each recording is its own file; route.json refs are the operational subset for THIS train. Other-platform takes the train doesn't use go to `audio/_archive/<line>/<diagram>/sta/`. Re-use surfaces as a glob (`ls *_gota-del-vient.mp3`). No metadata sidecar — filename IS the store.

2. **Variants intentionally out of scope.** Song slug captures song identity, NOT recording identity. `tsuga_2_gota-del-vient` and `monoi_1_gota-del-vient` share song identity; the actual recordings differ (different door chimes, possibly arrangement variants). Modeling that is deferred until pain forces it.

3. **Per-source splitter scripts**, not maintained library. Format varies between sources — sobu's two STA sources used different formats (3-timestamp explicit-end vs 2-timestamp implicit-end). Each source gets its own `split_<type>_<describer>.py` (`split_sta_higashichiba.py`, `split_sta_tokyo.py`). Per-segment `dest` tag (`"op"` / `"archive"`) routes files automatically — re-runs are idempotent.

4. **Stations with no IRL departure melody** (e.g. 千葉 on Sobu) get the same treatment as termini: omit `sta` and `sta_cut` from route.json. Keep `time` (it's the travel time TO this station from the previous one).

5. **"Discard variants for now"** — explicit user call. Door-chime / arrangement / pitch-shift differences are not modeled. Captured the user's broader stance: pragmatic over perfect, capture metadata as it surfaces, don't gate route work on schema research.
