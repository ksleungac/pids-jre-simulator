### CJK chrome refactor — pygame font discoveries

1. **Helvetica-only chrome tofus CJK.** Original tutorial chrome used `_font_helv` directly; CJK glyphs render as `.notdef` boxes. Switched to `_render_mixed(text, latin_font, cjk_font, color)` routing per-codepoint.
2. **ShinGoPr6N tofus Simplified-only glyphs.** ShinGoPr6N is JIS-based; has Traditional Chinese (zh-HK fine via JIS overlap) but tofus Simplified forms like 开, 进, 这. Need YaHei for zh-CN. Added `_font_cjk(size, *, heavy=False)` — language-aware: zh_CN → YaHei (covers Simplified); HK/EN → ShinGoPr6N (Japanese forms read right for embedded JP kanji like 国府津).
3. **`paragraph.split()` doesn't break CJK.** New `_wrap_atoms(text)` tokenizer: each CJK codepoint = one atom, each `[[...]]` chip = one atomic atom, Latin runs between spaces / CJK / markup = one atom each.
4. **Keycap baseline misalignment** (zh chip labels sat lower than surrounding text): `_render_mixed` claimed `latin_font.get_ascent()` for chip alignment, but chip's actual label baseline is `cap_y + pad_y + label_ascent` and CJK label-ascent > Latin. Refactored `_render_keycap` to return `(Surface, effective_ascent)` so callers align correctly.

### Translation register difference (zh-HK vs zh-CN)

- **zh-HK voice:** concise, conventional HK Traditional spelling (出發 not 出发, 教學 not 教程, 後 not 后). Code-switching English nouns (`你已完成 Tutorial`) kept where it reads naturally.
- **zh-CN voice:** independent translation, NOT a Simplified conversion of zh-HK. Mainland register avoids English code-switching (`你已完成教程!` not `你已完成 Tutorial!`). Vocab: 教學↔教程, 廣播↔广播, 月台↔站台, 餘下↔剩余, 抵達↔到达, 影片↔视频.

# 2026-04-30 (Late evening) — AutoDriver pa_at_station drain + vocabulary-discipline recurrence

## Actual fix (6 lines)

`auto_input.py:_fire_departure` gained a silent `pa_at_station` drain step before `pending_next_pa = True`. When user lagged on at-station announcements (Layer 1 = STOPPING, queue not exhausted) and the game departed (Layer 3 = APPROACHING_*), the synthesized PageDown press would consume one queue entry instead of advancing the segment — causing each subsequent FIRE_* event to play wrong audio (at-station entries for stop N playing while train approaches N+1). Drain sets `cnt_pa_at_station = len-1` so `_next_in_stopping` falls through to `_advance_to_next_stop` naturally. Channel 1 (synthesized press) remains the only audio-firing channel.

**Doc change:** `AUTO_INPUT.md § Vocabulary discipline` extended from 1 paragraph to 3 numbered rules: (1) use Layer 1/2/3 named states verbatim, (2) use arrow-flow notation for state progressions (not multi-column tables), (3) don't redesign the state machine.
