## Session 3: PA silence cleaning — voice-onset detection + tokaido/1865E trim

First data-task session on opencode. User wanted PA silence brackets cleaned on Tokaido 1865E. The existing `validate_pa.py` tool used a crude -40 dB threshold that couldn't distinguish recording hiss from voice; files with ~3 s of pre-voice noise floor would pass validation while leaving audible hum before PA announcements.

**Voice-onset detection.** Built `_dev_scripts/trim_pa_silence.py`: computes noise floor from file-wide quietest segments (clamped to -60 dB min), finds voice onset as the first frame exceeding noise_floor + 12 dB WITH a +6 dB/30 ms attack slope (sharp rise, not flat noise). Trims to ~80 ms pad before onset via ffmpeg stream-copy. Idempotent — re-running on already-trimmed files is a no-op.

**By-ear verifier.** Built `_dev_scripts/verify_pa_listen.py`: plays first 3 s of each PA segment, PASS/FAIL with editable notes, verdicts persist to `audio_src/<line>/<diagram>/pa_verify_results.json`. Covers both `pa` and `pa_at_station` entries (the STA verifier predates `pa_at_station` and only reads `pa`).

**Tokaido 1865E result.** 42 PA files trimmed. All 42 passed by-ear verification. 14 files flagged by the old -40 dB validator as MISSING LEAD — false positives (noise floor at -45 to -50 dB sits above the threshold but is clearly not voice per onset detection). Onset detector confirmed leads at 30-80 ms on all.

**Skill updated.** pa-make/SKILL.md Step 7 rewritten: three-step flow (onset-trim → validate → by-ear), two new tools added, two new gotchas.

**Trim+validate merged.** `trim_pa_silence.py` now runs `validate_pa.py` as final summary — one command replaces two.

## Session 4: Sensor buildout — automated rule enforcement

Systematic conversion of behavioral rules into automated sensors. Three tiers established:

**Pre-commit** (every commit): `lint_primitives.py` gained `_*/` production-import ban; `check_fonts.py` + hook added (.ttf ban).

**Build pre-flight**: `check_deps.py` — AST-walks all production files, verifies every third-party import is in `[project.dependencies]`. Alias map handles install-vs-import mismatches (`pywin32 → [win32, pywintypes]`). Wired into `/build` skill Step 2a. User preferred build gate over pre-commit for this one. `/build` skill also restructured: 6 manual steps → 3 (version → uninterrupted build+stage → zip after smoke test) — no step-by-step flexibility needed when no human decisions are required mid-flow.

**Session-start**: `check_harness.py` — parses `.claude/settings.json` + all SKILL.md files, verifies every referenced script exists on disk. Wired into `session_init.py`.

**PostToolUse(Edit)**: `stale_ref_hook.py` — after each Edit, diffs identifiers between old/new strings; if 1–3 removed (rename signal), greps codebase and injects stale refs as context. Replaces the "manually grep after renames" convention. Common-word false positives are expected noise (e.g. "installs" caught on first run — irrelevant match in AUTO_INPUT.md).

## Session 5: keihin/1275A PA trim + verify_pa_listen tail playback

Trimmed keihin/1275A (京浜東北・根岸線 快速) — 59 PA files, highest ROI route. Onsets ranged 0.22–2.35s, noise floors -25 to -44 dB. All 59 lead-trimmed to ~80ms pad. All 58 PA + 1 pa_at_station verified PASS.

**Tail playback added to verify_pa_listen.py.** Failed first attempt: `pygame.mixer.music.set_pos()` doesn't work for MP3s (repeated head instead of seeking). Second attempt: ffmpeg temp-file extraction — worked but overcomplicated. Final fix: `pygame.mixer.music.play(start=offset)` — same mechanism STA verifier uses. Reloads same file, seeks via `play(start=...)`, no temp files. Head auto-plays 0→3s, then tail auto-plays last 3s before EOF. State machine: HEAD → GAP → TAIL → DONE.

**Audio doesn't work when launched from bash tool** — pygame mixer can't reach user's speakers through the process tree. User must run GUI verification tools themselves; claude generates the `--only` filter from NOT_REVIEWED entries.
