# 2026-04-26 — Doc Reorganization (preloaded vs progressive split)

## Trigger

Another Claude (in a separate session) was working on a lower-LCD bugfix and skipped reading `LOWER_DISPLAY_UPDATE.md` despite CLAUDE.md saying to. Their reason: `notes.md` skip-logic content was already preloaded into context, and "I had enough" — but the deeper doc had a window-invariant table their fix violated. Their own diagnosis: discipline failure on partial-context completeness, not a discoverability problem.

That triggered this session's reorganization. Two structural problems:

1. **`notes.md` was a 205-line kitchen sink** with display gotchas, data validation rules, real-world conventions, etc. — content that should have lived in narrower-domain docs. Preloading it gave a false sense of completeness.
2. **No principle existed for what should be preloaded vs read-on-demand.** Documents drifted into `notes.md` because nothing reminded the next Claude *during* a session (only at `/session-recap`).

## Principles established (now codified)

- **Preloaded vs progressive disclosure.** Things humans keep in their head when working on the project — what it models, scope/policy, IRL framing — belong in `CLAUDE.md` and the rules files (always-loaded). Implementation details (draw-method gotchas, JSON-field minutiae) belong in domain docs and get read on demand. **The slim-CLAUDE rule applies to implementation, not framing.** Mental-model content can grow CLAUDE.md modestly because that's what CLAUDE.md is for.
- **Doc placement is an active-session concern.** Codified in `preferences.md` "Documentation Hygiene" so it's loaded at session startup, not only at recap. Banner at top of `notes.md` itself reinforces at the dumping-ground site.
- **In-code `# CONTRACT:` pointers as defense-in-depth.** "Read the doc first" instructions get bypassed when an agent has partial context that feels sufficient. An in-code 3-line contract comment lands in any agent's context the moment they read the file to edit it. Bypass requires deliberate dismissal vs omission. Format: summary + `DOC.md § "exact heading"` + "what breaks if skipped". Bar: non-obvious AND has bitten or clearly could bite.
- **Family-level scope policy** (now in CLAUDE.md Mental Model). Each train series only runs IRL on a fixed subset of JR East lines. The simulator accepts any route loaded into any model, but reality only constrains the in-spec subset. **Hard floor** for out-of-spec: no crashes / no missing-key errors / no broken layouts / behavior parity (same cycling, skip animation, view alternation as in-spec). **Soft floor**: graceful fallback (long names truncate, missing translations fall back, odd stop counts use existing layout regimes). **Not obligated**: IRL fidelity for a line the model never serves — no reference exists.

# 2026-04-26 — Continuity arrows + dest-terminus fix (separate session, same day)

## Trigger

User wanted the long-route's "route continues" indicators (`self.continuity` flags computed in `_calculate_layout` but read by *nothing* in the new modular `lower_lcd.py` — dead state since the refactor). Original `old_version.py` had commented-out `draw_continuity_r`/`draw_continuity_l` helpers that were dropped in the refactor.

## Continuity arrow design (full-route view)

**Architectural framing:** continuity is a *property of certain cells* (last-on-row-1, first-on-row-2, last-visible-when-window-slid), not a separate "element type". The `JapaneseDisplay.show_stops` cell loop draws each variant inline alongside the cell so color inherits from cell's active/passed state — no separate threshold logic, no floating shapes that drift away when the bar gray-outs.

User's words: "include the continuity arrows as a different variant while drawing the station bars … reduces the complexity for defining a new set of elements."

**Three slots:**
- Slot 0 (row-1 tail, `continuity[0]`) = "to" indicator: bar → 分-area → triangle (apex right, off bar's tail) → chev1 → chev2.
- Slot 1 (row-2 head, `continuity[1]`) = "from" indicator: chev1 → chev2 → bar with WHITE_BG inverse-triangle notch carved INTO bar's left edge.
- Slot 2 (last visible cell when window slid, `continuity[2]`) = same as slot 0.

**Visually asymmetric "to" vs "from"**: outward triangle on tail vs inward notch on head. Per IRL `lcd_references/chev.png` and `chev2.png` references. (I had it backwards in early iterations — "to" is the *triangular* tail, NOT the chevron stack. User vocabulary: "to" = end-of-row, "from" = head-of-row.)

**Tip-portion uniformity (the critical geometry):** for all three gaps (triangle→chev1, chev1→chev2 at top/bottom AND at the V-shape center) to render as a uniform 4-px white margin, set `tri_w == cont_chev_w − cont_chev_stroke == 8`. Currently `cont_tri_w=8`, `cont_chev_w=12`, `cont_chev_stroke=4` → tip-portion = 8 = `tri_w`. Also matches the red cursor's tip-portion (`w − stroke = 18 − 10 = 8`) so apex slopes read consistently across the LCD.

**Negative chevron gap:** `cont_chev_gap = -4` overlaps chevron BBs. The visible whitespace is NOT the gap value — chevron's tip protrudes into its own BB, so visible gap at top = `cont_chev_gap + (cont_chev_w − stroke)`. For 4-px visible whitespace at top, `gap = -4` (BB overlap by 4).

**Slot 1 bar compensation:** notch carves `cont_tri_w` into the bar's left edge. Without compensation, visible bar would be `cont_tri_w` narrower than other cells. Cell loop adds `cont_tri_w` to `bar_w` (and shifts `bar_x` left) for slot-1 cells. Drawing order = bar → notch (white, overdraws bar) → chevrons (cell-color, overdraws notch where chev2's tip extends in → tip "nestles" into the V).

**Color inheritance**, no threshold:
- Old approach: explicit threshold per slot (`curr_stop >= per_line` for slot 0, etc.).
- New approach: `cell_color = self.color if (gi >= cursor_pos and gi <= dest_idx) else INACTIVE_COLOR`. Continuity inherits.
- Same condition the bar already uses for its own active/passed coloring. Eliminates per-slot threshold magic.

## Row-end / row-head bar extension

Independent of continuity: every row-tail cell gets `+row_tail_extra = 10` px on the right; every row-head cell gets `+row_head_extra = 10` px on the left. Three rendering surfaces must stay in sync:
- `lower_lcd.py` `JapaneseDisplay.show_stops` cell loop (source of truth)
- `lower_lcd.py` `JapaneseDisplay.draw_times` 分-marker block (`cell_extra = 10` mirror)
- `lower_lcd.py` `JapaneseDisplay.draw_ptr` curr_stop==0 pentagon (`head_extra = 10` mirror)

Foot-gun. CONTRACT comments at the mirror sites point at `DISPLAY.md § "Row-end / row-head bar extension"`.

## State-leak fix on `continuity[2]`

`_get_stops_list_disp` previously set `continuity[2] = 0` only at the EXACT transition moment `remaining == STOPS_QUANTITY - 1`. Once the window slid further (e.g. user jumped to `curr_stop = 25` on Keihin), the flag stayed at the initial `[1, 1, 1]` and slot-2 chevrons rendered past the destination 大船 — visible bug.

Fix: recompute `continuity[2]` on every call. `0` when window has slid (visible window includes route's last stop, no more route past it); `1` when window is at original position and route has > 28 stops. Circular routes (Yamanote) keep `[1, 1, 1]` since the route always continues via the loop.

## Dest as terminus (Isogo / 727B fix)

User: "try with 727B isogo, when train arrived at isogo, one more pagedown makes it go ofuna which is not desired."

`_next_pa` was checking `if self.state.curr_stop < len(self.stops) - 1`, i.e. the JSON's last entry. But Keihin 727B's `dest = "磯子"` (index 40) and stops continue 41..45 from 磯子 to 大船 — extra stops are operational reference for through-running. Train should terminate at 磯子.

Fix: `PASimulator.__init__` resolves `self.dest_stop_idx = next((i for i, s in enumerate(self.stops) if s.get("name") == self.dest), len(self.stops) - 1)`. `_next_pa` uses `terminus_idx = (len(self.stops) - 1) if self.state.circular == 1 else self.dest_stop_idx`. Circular routes (Yamanote) intentionally don't use `dest_stop_idx` — they have stop-level dest cycling and rely on the loop-back branch; a duplicate name match (first vs last station of a loop) would be wrong here but is harmless for circular routes.
