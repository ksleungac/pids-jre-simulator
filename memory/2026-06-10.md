### Pathology worth keeping (not play-by-play)

- **Continuity-at-junction was a framing bug, not a drawing bug.** Slicing `display_stops` to the active frame made the renderer read the junction (千葉) as the route terminus, so the "route continues" indicator vanished. Correct fix = compare the window's GLOBAL position against the full route (`_frame_global_lo + last_gi < len(_full_display_stops)-1`), leaving draw code untouched. I reached for draw-side overrides first (`or _frame_continues`, `continuity[2]=1`) across several rounds — root of the session friction (see codifications).
- **Separate pre-existing 8-station drawing bug surfaced**: the continuity triangle floats past the red pentagon when the train sits on the last visible cell, because `draw_times` skips that cell's 分-area (so the bar never extends to meet the triangle). Fixed by painting the 分-area extension before the pointer. Frames exposed it because pre-frames the last cell was always the true terminus.
- **Swap fire is boundary-aligned by construction**: `_handle_at_station_edge` resets the view-cycle to its anchor slot on the STOPPING-edge at the same instant arm records its time, so `arm + rotation_dur` lands on the slot rollover (no mid-page cut). Only a no-transfer junction would misalign — latent, logged to TODO deferred-findings.
- **JR logo = flattened-bezier vector polygon** (`draw_jr_logo` in utils), not a rasterized asset: no SVG rasterizer in the env, AND it's deployment-safe (no SDL-image SVG dependency, nothing read at runtime, no `/build` bundling).
