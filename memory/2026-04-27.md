- **Auto-segment from multi-station source** — new Step 1.5 in skill. 50 ms RMS envelope, classify silences by next-active duration (>6 s → between-segments, 1.5–6 s → mid-gap, <1.5 s → voice-break). Surfaced 18 segments cleanly; user confirmed mapping.
- **3 source-recording artifact patterns** discovered:
  - **A — KAK transient** (physical staff-cut click captured in audio, peaks -4 to -7 dB, 0.2–0.5 s). Algorithmic detection via 25 ms peak-amplitude envelope walk works reliably. 14 stations spliced.
  - **B — 2nd-loop snippet** (recording captured the start of a 2nd melody loop before staff cut, often paired with 2-3 s post-snippet silence). Splice removes both; normalize to ~1 s music→voice gap. Applied to 6 stations: chiba-minato, inage-kaigan, kemigawahama, minami-funabashi, futamata-shimmachi, ichikawa-shiohama.
  - **C — Per-file artifacts (stutters, duplicate intros)** explicitly defer to verifier interactive trim (don't try to detect; envelope shape is indistinguishable from legitimate variation). shin-kiba had a 0.2 s start stutter — fixed by user via the trim feature.
- All 17 stations passed by-ear gate.

## verify_sta_listen.py upgrades

- **Per-station notes** (✎ row above seek bar): click or `E` to add/edit, Enter saves, Esc cancels. PASS auto-resolves the note (renders dim with strike-through). Persisted in `sta_verify_results.json`.
- **Cut-marker beep**: short 880 Hz tone fires once per playback when tail crosses sta_cut. Audibly marks the transition point — easier to tell whether the cut lands cleanly.
- **Interactive trim**: `[/]` start, `,/.` end (Shift = fine 0.01 s); `R` previews pending trim (head plays from `trim_start`, tail stops at `duration−end_trim`); `T` applies via lossless ffmpeg splice and shifts `sta_cut` by `−start_trim`, persisting to route.json. Workflow for any per-file issue that defies algorithmic detection.
- **ffmpeg auto-discovery**: PATH first, then winget Gyan.FFmpeg / chocolatey / standard install paths (with version-glob). Fixes "trim failed: file not found" when verifier launched from a shell without ffmpeg in PATH.

## trim_sta_silence.py fix

- Regex-based sta_cut patcher silently failed on multi-line `"sta": [\n  "X"\n]` format (default `json.dumps(indent=4)` output). Caused several keiyo sta_cut updates to be missed in earlier runs (including the 大宮 multi-element sta on 1349F, manually patched at the time). Replaced with json parse + write — handles compact AND multi-line, single AND multi-element sta lists. Re-emits with `indent=4` (project convention).

## Preferences locked in (also captured in skill / preferences as appropriate)

- **0.5 s pre-voice** is the default sta_cut placement rule.
- **Build feedback tools, not over-fit detectors** when source patterns vary per-file.
- **Skip-confirmation on routine session-end commits** when the user explicitly says "push directly" — the /commit skill's confirmation gate can be bypassed with that signal.
- **Filename convention reminder**: `{station}_{platform}_{song-id}.mp3` with platform and song-id optional. Drop separators when fields unknown. Use Hepburn slug, lowercase, hyphens within fields, underscores between.
