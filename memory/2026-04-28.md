### State-machine PASSING bug — caught by live drive

Keiyo 千葉みなと→稲毛海岸 leg crosses **千葉貨物** (Chiba Freight Terminal — non-passenger waypoint). Game HUD flips badge to PASSING when crossing it. Detector previously only reset `departure_fired` / `arrival_fired` on `STOPPED→MOVING`. `STOPPED→PASSING` fell through silently — flags inherited `True` from previous segment, speed-crossing departure check short-circuited, arrival check stayed gated on `badge==MOVING` (which never resolved within this segment for ~80s), eventual `passing_end` saw `arrival_fired=True` and skipped. **Train arrived with no PA played.**

Fix (`8ac2b67`): `STOPPED→(MOVING|PASSING)` both reset flags. Symmetrically `(MOVING|PASSING)→STOPPED` both emit arrival. Mid-segment `MOVING↔PASSING` stays silent (legitimate within-segment waypoint crossings). Mirrored in `_dev_scripts/capture_game.py`.

**Side note for future Claude:** PASSING badge ⊄ "non-passenger waypoint" — also fires for passenger passing-through stations like 幕張豊砂. Badge means "currently passing through *something*"; what kind is independent of the badge.

### Plot dashboard architecture lesson

Plotly's title HTML support is too restricted (no tables, complex layouts). Wrap multiple per-section charts in real HTML page with CSS for everything around the charts. Plotly is the chart engine, not the layout engine.

### Schema discriminator quirk worth knowing

`_stops_here = bool(s.get("time") is not None)`, NOT `bool(pa)`. Per project convention, passing-through stations have NO `time` field; stopping stations always have one (even `time: 0` for the start station). Earlier `bool(pa)` was wrong for terminus / start stations with empty `pa` lists.

## Session: Evening — STOPPING state: pa_at_station schema + unified state machine + lower-LCD pentagon

User's framing: STOPPING needs to exist as a real state before click-to-jump can proceed (because the natural landing target for a click-jump is "I'm at platform X" = STOPPING, not "次は X" = APPROACHING).

### Schema decision (option A, two-list split)

Each stop has both `pa` (pre-arrival sequence) and optional `pa_at_station` (at-platform sequence). Default-empty `pa_at_station` covers the typical 2-PA stop with zero migration cost. Considered B (single list + `arr_idx` boundary) and C (per-element tag); rejected — A mirrors IRL split cleanly + matches filename-as-store + minimal-JSON principle + keeps every existing route untouched.

**Migration finding:** Tokaido 1865E 鴨宮 had `pa: ["27","28","29","30"]` — but 27/28 were at-platform tracks for the **previous** station (国府津 — Gotemba Line junction with extra at-platform announcements). Migrated: 国府津 gains `pa_at_station: ["27","28"]`; 鴨宮 stays as standard 2-PA. 1865E 東京 also moved from `pa: ["1"]` to `pa_at_station: ["1"]` (welcome announcement semantically fits at-platform).

### Unified state machine — APPROACHING ↔ STOPPING

**Mental model:** every stop cycles `STOPPING → advance press (plays next.pa[0]) → APPROACHING (cycle pa[]) → exhausted → enter STOPPING (no audio) → cycle pa_at_station → exit via advance`. Boot at curr_stop=0 starts in STOPPING (train parked at start platform).

**Upper LCD prefix mapping cleaned:** old `cnt_pa >= 2 → ただいま` was a wrong-stop-ambiguity hack — pre-migration data had at-platform PAs of station X-1 packed into station X's `pa[2+]`, so display said "ただいま X" while audio referred to X-1's platform. New mapping: `at_station → ただいま` (the ONLY path), `cnt_pa == 0 → 次は`, `cnt_pa >= 1 → まもなく`. Removing the fallback closes the semantic loophole.

**Circular loop-back collapsed into normal advance.** Pre-unified-model: idx N → idx 0 → press → idx 1 (2-press hop with no audio at idx 0). New: idx N → idx 1 directly. Duplicate idx 0 in Yamanote-style routes is a structural marker for circularity, not a state to visit mid-loop.

### `time` field semantic correction

User: "time at shimbashi is 0 to be honest, as we've arrived at shimbashi." Closer look revealed DATA_FORMAT.md said "Travel time to next station" (outgoing) but data + render code consistently treat it as INCOMING from N-1 (1865E 東京.time=0, 新橋.time=2 ≈ 東京→新橋). Schema doc was wrong; corrected. `draw_times` skips render at curr_stop when at_station=True; first rendered cell after the skip uses `stops[gi]["time"]` directly (no countdown carryover).

### Final-approach-PA prefix rule

Replaced `cnt_pa >= 1 → まもなく` with `cnt_pa == len(pa) - 1 → まもなく`. User's stated rule: *"if there's new cases where there are 3 PAs, always the last PA triggers the まもなく."* Generalizes from 2-PA to N-PA cleanly. For current 2-PA data: identical rendering. Slight behavioral change for 1-PA stops (used to stay 次は forever in APPROACHING; now show まもなく immediately) — semantically correct since the only PA *is* the final approach.

### AutoDriver `FIRE_AT_STATION` hook

Pattern: per-segment `at_station_fired` flag + level test (`badge==STOPPED AND arrival_fired AND not at_station_fired`).

**Why `arrival_fired` is the prerequisite:** without it, the level test would fire on the first capture cycle when the train is parked at the start station (boot scenario), desyncing the simulator before the first real drive. `arrival_fired` ensures we're in the stopping moment of *this* segment, not at session boot or post-jump.

### Yellow hint square generalized to STOPPING

Existing rule: yellow when `len(pa) > 1`. New: when `at_station=True`, check `pa_at_station` instead — yellow when `len(pa_at_station) > 0`. Different threshold because `pa` is 2-by-default and `pa_at_station` is empty-by-default; `>0` captures "there's anything to play while parked."
